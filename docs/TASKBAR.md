# Настройки системной панели задач

Используются собственный Win32-адаптер и DLL Explorer без Windhawk.

## Автоматическое применение

Четыре стороны, ширина/длина, слитный/отдельный вид, прозрачность и автоскрытие снизу применяются после
действия пользователя. UI объединяет быстрые изменения одноразовым таймером
180 мс. Пока native-запрос pending, последнее изменение удерживается и отправляется
после завершения. Кнопки «Применить» нет; восстановление оставлено отдельным действием.
Загрузка страницы/значений не изменяет Windows и не создаёт polling.

Native-адаптер не отправляет повторное уведомление края, если край не менялся,
не перезаписывает исходный журнал без новых снимков и не пересоздаёт регион без
изменения геометрии/вида. Неизменившееся автоскрытие повторно не записывается.
Прозрачность реализована через alpha всей панели, включая значки; это не blur только фона.

## Размеры и боковая раскладка

UI Automation на этой машине подтвердила, что нативное уведомление переносит
HWND к боковому краю, но оставляет содержимое горизонтальным. Прежняя проверка
только ABM_GETTASKBARPOS ошибочно считала такой перенос рабочим. Обычную установку
меньшей ширины через SetWindowPos Windows сразу отменяет.

Теперь собственная DLL обрабатывает размеры внутри Explorer и вызывает настоящий
reflow. Ползунок 40–100% появляется в отдельном виде; сбоку он задаёт длину.
Боковые режимы используют штатную вертикальную раскладку значков и трея, доступную
в проверенных системных DLL. На несовпадающих сборках Windows кнопки боков отключены.
Обрезки содержимого нет. Подробные GUID/смещения, механизм и ограничения описаны в
[решении о нативной раскладке](TASKBAR_NATIVE_LAYOUT.md).

## Возврат состояния

До первого изменения сохраняется атомарный журнал вне установки и запускается
отдельный процесс восстановления. До 16 снимков содержат HWND/PID/время создания,
исходный регион и alpha; при восстановлении проверяется системный explorer.exe.
События геометрии приходят через out-of-context WinEventHook, объединяются и
не вызывают повторную установку того же региона. Отдельный вид имеет отступ 6 DIP.

Штатный выход/сброс возвращает край, размеры, исходный TaskbarLocation, alpha и регион.
Локальные биты кэша функции Windows возвращаются при снятии сессии. Автоскрытие остаётся выбранной
системной настройкой. Worker ожидает handle родителя/stop event без polling и GPU;
при смерти родителя читает журнал. Совместный сбой GUI/worker и потеря питания
не покрываются. --restore-taskbar-style пытается восстановить оставшиеся журналы.
Ярлык и вызов recovery при удалении есть в исходниках установщика, но VM-проверки не было.

## Проверки

Python-прототип проверил alpha/region, обычное восстановление и возврат после
os._exit родителя. QML-тест tests/taskbar_live_ui_test.py проверяет отсутствие
стартовой записи, объединение burst-событий, последнее значение при pending и
отказ неподдерживаемых режимов и доступные стороны/ширину без Win32-адаптера.
Собственные C++ DLL/host собраны MSVC и проверены на двух мониторах 96 DPI: четыре
стороны, размеры 40–100%, реальная вертикальная геометрия кнопок/трея по UI Automation,
возврат геометрии/registry после обычного выхода и смерти host. Ручное применение из C++ GUI,
все flyout/drag-and-drop, другие DPI/RDP, ресурсы GUI и installer/VM не проверены.
Автоскрытие остаётся доступным снизу при полной ширине. Включение возвращает 100%
и временно отключает ползунок ширины. Запрос слева Windows отклонила; при уменьшенной
ширине нативное скрытие нестабильно, поэтому сочетание не предлагается.
Гарантии на другие Windows 11 нет.

[ABM_SETSTATE](https://learn.microsoft.com/en-us/windows/win32/shell/abm-setstate) ·
[ABM_GETSTATE](https://learn.microsoft.com/en-us/windows/win32/shell/abm-getstate)

## Группы и толщина

«Островки» убирают общую подложку и объединяют элементы в группы: погода/виджеты,
Пуск/поиск/приложения и системный трей. Между группами остаются прозрачные промежутки;
в них клики проходят к находящимся под панелью окнам/рабочему столу. Штатные составные
кнопки Windows не разделяются. На втором мониторе набор групп зависит от Windows.

«Толщина» меняет высоту горизонтальной или ширину боковой панели (48–96 DIP),
сохраняя размер значков Windows. Островки используют минимум 64 DIP, при включении
выбирается 72 DIP для дополнительных отступов. Все изменения применяются автоматически.
Автоскрытие возвращает обычную панель толщиной 48 DIP и шириной 100%.

### Выбор вида и размеры

Вместо отдельного переключателя островков доступны три кнопки «Вид панели»:
«Слитный», «Отдельный», «Островки». Общая подложка отдельной панели и групповые
подложки островков взаимно исключены. Ползунок ширины (сбоку — длины) 40–100%
доступен для обоих пользовательских видов и расположен перед высотой/толщиной.
У слитной панели оба ползунка скрыты: она полноразмерная, стандартной толщины 48 DIP.
Автоскрытие в островках недоступно; сначала нужно выбрать другой вид.

Скругления пользовательских видов рисует композиция Windows со сглаживанием;
области ввода между группами остаются раздельными. При расположении сверху окно
скрытых значков открывается под панелью, снизу — над ней, сбоку — внутрь экрана.
