# Решение: собственный модуль нативной раскладки Taskbar

Статус: реализовано и проверено локально для конкретных системных DLL. Это не
обещание совместимости со всеми Windows 11. Windhawk и его исходники/движок
не являются зависимостями реализации.

## Причина и выбранный механизм

Внешний SetWindowPos Explorer немедленно отменяет. Одно уведомление 0x5CA/6
переносит HWND, но на исходной конфигурации оставляет значки горизонтальными.
Обрезка существующей панели скрывала бы значки и трей.

UmbrellaTaskbarHost ставит WH_CALLWNDPROC только на потоки проверенных системных
Shell_TrayWnd/Shell_SecondaryTrayWnd, максимум 16 окон. Собственная DLL устанавливает
SetWindowSubclass на том же UI-потоке. Она меняет WINDOWPOS после штатного обработчика,
сохраняя монитор, толщину и допустимое движение штатного автоскрытия. Размер клиентской
области вызывает настоящий reflow XAML, включая overflow при узкой панели.

Для боков в установленной сборке уже существует нативный путь TaskbarLocation,
закрытый внутренней функцией 59213768. DLL временно меняет три бита её локального
кэша в Taskbar.dll, Taskbar.View.dll и SystemTray.dll. Исполняемый код, глобальная
конфигурация функций Windows, политики оболочки и автозапуск не меняются.
HKCU Explorer/Advanced/TaskbarLocation сохраняется перед изменением и восстанавливается.
Остальные биты кэша сохраняются при возврате через compare-exchange.

## Точное ограничение сборки

Адреса данных получены из соответствующих PDB Microsoft Symbol Server. Перед записью
DLL проверяет RSDS GUID и age=1 всех трёх загруженных образов и writable memory:

| DLL | RSDS GUID | RVA кэша |
| --- | --- | --- |
| Taskbar.dll | DAB69A79-FEE0-33F0-D81E-023FBF172B51 | 0x23BE38 |
| Taskbar.View.dll | 24534974-E00E-46A5-8F69-F60D0CEB9BD9 | 0x92EE10 |
| SystemTray.dll | 2007F389-0B9D-4D16-AF78-BAFE77122728 | 0x1EDDB8 |

Проверка UI читает установленный образ как данные, без выполнения DllMain, и не
заменяет повторную проверку загруженных DLL. На неизвестной сборке боковые режимы
отключены. Новые смещения нельзя добавлять без отдельного исследования и desktop/VM
проверки. Во время работы загрузок символов или бинарников из сети нет.

## Время жизни и восстановление

Обмен фиксированным versioned WM_COPYDATA ограничен шириной/длиной 40–100% и четырьмя
краями. DLL проверяет HWND класса владельца и полный путь sibling-host. Это ограничение
команд, а не граница безопасности против другого процесса того же пользователя.
Handshake не меняет расположение панели. Один владелец управляет одной subclass-сессией.

На каждое окно есть ожидающий native-поток: он ждёт handle владельца/stop event,
без таймера и polling. Смерть host вызывает восстановление на UI-потоке. Синхронный
message round trip завершает callback перед FreeLibraryAndExitThread. При зависшем
UI reference DLL сохраняется до окончания Explorer, чтобы не оставить висячий callback.
Обычный выход снимает subclass/hook и закрывает handles. Explorer не завершается.

Внешний journal/worker дополнительно сохраняет TaskbarLocation, край, alpha и регион.
Одновременный сбой всех участников, потеря питания и зависание Explorer не покрываются.
Автоскрытие остаётся выбранной системной настройкой и доступно снизу при 100% ширины.
Этот режим не перехватывает native WindowPos; уменьшенная ширина нестабильна со штатным
autohide, поэтому переключатель явно возвращает 100% и блокирует уменьшение.
Когда окно скрыто за краем, внешний адаптер снимает отступ региона, сохраняя область
показа по наведению. При неизменной форме движение не пересоздаёт регион на каждом кадре.

## Проверки и ограничения

- C++20 DLL/host собраны Microsoft MSVC 14.42 x64 с Windows SDK 10.0.26100.
- --fixture проверяет удержание размера, отказ 39/101% и возврат отдельного тестового окна.
- На двух мониторах 2560×1440/96 DPI проверены четыре стороны, 40/65/75/80/100%,
  отдельный вид, alpha и восстановление registry/геометрии после обычного выхода и
  принудительного завершения только собственного host.
- UI Automation подтвердила вертикальные Start/значки/tray слева и справа; при 40%
  горизонтальной ширины видимые кнопки остались внутри панели. Содержимое окон не копируется.
- В одной серии ширина после подключения подтверждалась за 7–39 мс; это latency команды,
  не FPS или гарантированная оценка на другом компьютере. Измерения полного GUI/GPU
  и масштабирования ещё не сделаны.

Описанные локальные desktop-наблюдения получены в Python/Qt-просмотре с C++ DLL;
статус полной C++ сборки вынесен в VERIFICATION.md.
Другие DPI, RDP, смена топологии, installer/VM и все flyout/drag-and-drop сценарии
остаются отдельной проверкой. Путь внутренней функции не является контрактом Microsoft.

API: [SetWindowsHookExW](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-setwindowshookexw),
[SetWindowSubclass](https://learn.microsoft.com/windows/win32/api/commctrl/nf-commctrl-setwindowsubclass).

## Толщина и «Островки»

Толщина 48–96 DIP управляет короткой стороной HWND с учётом GetDpiForWindow.
Островки — три группы реальных контролов Windows, а не отдельная подложка каждой
кнопки: виджеты, Пуск/поиск/приложения, трей. Группы получают общий поперечный размер,
продольные поля 8 DIP и промежутки минимум 8 DIP до дополнительного скругления.
При выборе вида QML использует сохранённую в странице толщину (изначально 72 DIP); ползунок допускает 64–96 DIP.
Нативный размер значков сохраняется. Режим несовместим со штатным автоскрытием:
его включение явно выключает островки и возвращает 48 DIP/100% ширины.

UIA работает в отдельном MTA worker host; восстановление не зависит от его
успешного ответа. Читаются структура и координаты, не содержимое открытых окон.
Границы обхода — 512 узлов/панель и 16 панелей. Подробности владения/отказов —
ARCHITECTURE.md. Поддержка иных DPI и всех flyout/drag сценариев не проверена.

--fixture дополнен проверкой толщины, недопустимых 47/97 DIP, трёх непересекающихся
регионов, пустой и устаревшей масок. Эти проверки не подтверждают полный Qt C++ GUI;
Windows-проверка использует тот же native DLL/host через Python/Qt-просмотр.

Группы/толщина проверены на двух мониторах 2560×1440 при 96 DPI: 48/72/96 DIP,
четыре стороны, подтверждение регионов на обеих панелях, выход и завершение только
собственного host. Живой QML-путь проверен для переключения групп, последней толщины
после серии изменений и возврата исходных геометрии/регионов. Измеренное CPU-время
host за один 5-секундный интервал без действий — 0,00 с; это не оценка нагрузки GUI
или гарантированный результат на другом ПК. При одном измерении working set host
с UIA был около 17 МиБ, private bytes — около 3 МиБ (первый вариант маски, до группировки).

Островки выбираются как вид панели вместе со «Слитным» и «Отдельным». Для размеров
они используют detached=true; поэтому ползунок ширины/длины теперь управляет
также нативной областью групп. Слитный вид нормализует толщину в 48 DIP, скрывая
оба ползунка. Геометрический протокол DLL/host при этой правке не менялся.

## Проверка исправления внутреннего размера

Для дополнительной высоты/толщины модуль масштабирует native-подложку относительно
центра и центрирует SystemTrayFrame по короткой оси. Размеры самих XAML-фреймов
и кнопок не меняются: прямое изменение Height вмешивалось в кэш высоты Explorer. Исходные локальные свойства принадлежат всей сессии owner;
перед поворотом и восстановлением overrides всех мониторов снимаются совместно.
Это устраняет сохранение предыдущего пользовательского размера в качестве исходного.

Опциональная проверка (меняет текущую панель, другие сессии Umbrella должны быть
закрыты): `tests/taskbar_native_alignment.ps1 -HostPath <путь к UmbrellaTaskbarHost.exe>`.
Она использует UIA-классы и координаты без чтения названий приложений/текста;
сравнивает центры кнопок приложений и трея с геометрией панели 48/72/96 DIP и проверяет
возврат геометрии после EOF. C++ GUI и прочие DPI остаются отдельной проверкой.

## Сглаживание и overflow-панель

Configuration v3 содержит detached отдельно от islands: отдельная панель шириной
100% тоже получает compositor clip. Host принимает четыре legacy поля и новый
запрос width/edge/thickness/islands/detached; новый клиент получает пять полей
подтверждения. Геометрия сглаживания больше не рисуется CreateRoundRectRgn.

Overflow располагается под верхней панелью, над нижней или рядом с боковой,
с отступом 8 DIP и ограничением координат монитором. --fixture проверяет настоящий
subclass на скрытом тестовом окне этого класса в своём процессе: top/bottom,
изменение размеров и координаты за экраном. Пользовательский трей тест не открывает.
Календарь и Quick Settings этой правкой не охватываются. Пользователь подтвердил
обе правки в текущем просмотре. Другие DPI/RDP остаются отдельной проверкой.

API: [Visual.BorderMode](https://learn.microsoft.com/uwp/api/windows.ui.composition.visual.bordermode),
[CompositionGeometricClip](https://learn.microsoft.com/uwp/api/windows.ui.composition.compositiongeometricclip).
