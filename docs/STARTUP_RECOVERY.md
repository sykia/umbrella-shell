# Восстановление после входа в Windows

После успешного изменения оформления Umbrella записывает пользовательский INI
`%APPDATA%/UmbrellaShell/Taskbar.ini` и HKCU Run/UmbrellaShell. Запись содержит
абсолютный путь к этому exe и `--resume-settings`. Этот запуск создаёт скрытое
окно-владельца, без показа настроек. Помощник контекстного меню остаётся отдельным.

Закрытие окна скрывает редактор и сохраняет оформление. Полный выход завершает
сеанс и возвращает исходное оформление, сохраняя выбранные параметры для следующего
входа. «Вернуть исходный вид» также сохраняет `resumeAppearance=false` и убирает
Run-запись. Следующее явное изменение снова включает восстановление.

## Готовность и единственный владелец

`TaskbarRuntime` владеет mutex текущего пользовательского сеанса. Повторный запуск
редактора показывает существующее окно; повторный `--resume-settings` его не показывает.
Recovery worker запускается тем же exe с `--taskbar-watch`; это отдельный процесс
восстановления, а не второй GUI-владелец.

Применение начинается после проверки системного пути Explorer, наличия панелей
активных экранов и ненулевых размеров. Готовность настоящего XamlRoot/контролов
подтверждает native-host при применении; наличие дочернего bridge HWND не требуется
(Windows может убрать его после Task View, сохраняя рабочую XAML-панель).
Учитываются TaskbarCreated, WM_DISPLAYCHANGE и WinEvent создания/геометрии окон.
Проверка выполняется сразу по событию. Если bridge уже существует, но native-handshake
ещё отказывает, разрешены до трёх попыток с одноразовыми интервалами 200/400 мс.
Если событие создания потерялось или пришло до доступности окна, включается
ограниченная перепроверка предиката готовности с backoff: до 16 проверок в пределах
30 секунд. Новое событие прерывает ожидание и проверяет готовность сразу.
В простое периодических проверок нет. При новом Explorer или составе экранов
старый native-сеанс закрывается и создаётся новый с новым журналом восстановления.
Основная панель и дополнительные панели ищутся по точным классам через FindWindowEx;
на исследованной Windows основная панель не всегда попадала в EnumWindows.

## Параметры экранов

`appearanceProfilesV1` содержит до 16 профилей. Ключ — SHA-256 системного
monitorDevicePath из QueryDisplayConfig; HWND, номер DISPLAY и порядок экранов
не служат ключом сохранения. GDI device name разрешается заново при восстановлении.
Отключённый монитор не удаляется из INI. Старый общий набор параметров используется
как начальное значение для экранов; при первом изменении создаются независимые записи.

Для каждого экрана сохраняются стиль, ширина, толщина, прозрачность и сторона.
Островки используют только панели, для которых включены островки; остальные панели
не участвуют в подтверждении UIA-масок. Разные верхняя/нижняя стороны передаются
отдельно. Нативный механизм боковой раскладки использует общую настройку Explorer:
разные боковые стороны экранов не обещаются; несовместимый выбор сохраняется,
но при восстановлении используется совместимая общая сторона с сообщением.
Автоскрытие — общая настройка Windows. Оно восстанавливается только при нижних
панелях полной ширины 48 DIP без островков на всех применяемых экранах.

Неподтверждённая новая попытка изменения не заменяет прежний профиль. Отказ
нативного применения возвращает предыдущие значения в INI. При несовместимости
после обновления Windows сохранённый профиль не переписывается значениями fallback.
Это безопасный пропуск функции, а не заявление о её применении.

## Конструктор компонентов

Черновики `componentDraftsV1` отделены от `confirmedComponentV1`. Последний содержит
только сценарий, который native-host подтвердил после действия пользователя.
Автовосстановление ограничено Task View после Widgets на основной исходной панели
при проверенных DLL, DPI 100%, полной ширине 48 DIP и без другой сессии оформления.
Произвольные черновики и перестановки второй панели автоматически не применяются.
При несовместимости подтверждённая запись сохраняется для будущей попытки.
Старые QScreen-ключи черновиков читаются при однозначном совпадении имени экрана;
они не превращаются в подтверждённое размещение.

## Проверка установленной сборки

После подтверждённого обновления:

1. Проверьте оформление обоих экранов. Измените поддерживаемые параметры каждого
   экрана и закройте окно. Настройки должны сохраниться без кнопки «Применить».
2. Вручную выйдите из учётной записи Windows и войдите снова. Перезагрузка также
   допустима, но агент не выполняет ни выход, ни перезагрузку самостоятельно.
3. Убедитесь, что окно настроек не открылось, а обе панели выглядят как перед выходом.
4. Запустите установленный `UmbrellaShell.exe --startup-status`: это читающая команда.
   `ownerPid` и `timestampUtc` должны относиться к новому сеансу, `succeeded` — true;
   проверьте `status`, размеры, alpha и оба устройства в `panels`.
5. Отдельную проверку настоящего перезапуска Explorer выполняйте вручную, если она
   согласована. Доставка TaskbarCreated тестом не заменяет реальный перезапуск.

Отчёт находится в `%LOCALAPPDATA%/UmbrellaShell/UmbrellaShell/startup-status.json`.
Он записывается по действиям/событиям, не содержит имён приложений или секретов.
Успешная проверка модели, повторного запуска процесса и событий не подтверждает
настоящий вход в Windows. До шага 2–4 этот этап остаётся незавершённым.

## Подготовка обновления

`Build-Local.ps1` использует уже извлечённые MSVC 14.42, SDK 26100 и Qt 6.8.3,
когда CMake/зарегистрированная VS недоступны. Это прямая компиляция MSVC, не прогон
CMake presets или Inno. Стандартный CMake/MSVC путь остаётся поддерживаемым.

`Prepare-LocalUpdate.ps1` создаёт отдельный runtime и manifest SHA-256 из построенных
пяти продуктов и существующего проверенного Qt runtime. Установленная копия не меняется.
После разрешения владельца `Install-PreparedUpdate.ps1` проверяет manifest, сохраняет
копии INI, Run-записей и установленного каталога, штатно завершает владельца и helper,
затем копирует runtime и запускает скрытое восстановление. Данные вне установки
не удаляются. При ошибке копирования запрашивается возврат прежних файлов из копии.
Это локальное обслуживание неподписанной development-сборки; не автоматический
updater, не атомарная установка и не гарантия отката после потери питания.
