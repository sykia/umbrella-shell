# Закрытие настроек и время жизни оформления

Закрытие окна, Escape и Alt+F4 скрывают настройки. Приложение продолжает владеть
TaskbarSettings, настройками в памяти, сеансом native-модуля и worker восстановления.
Поэтому край, островки, размеры и прозрачность не откатываются из-за закрытия окна.
Само окно не уничтожается: повторный обычный запуск того же установленного exe
и пункт Umbrella возвращают тот же экземпляр с текущими значениями.

В меню ПКМ панели есть «Завершить Umbrella». Эта команда завершает процесс GUI;
RAII-деструкторы возвращают исходное оформление так же, как раньше. «Вернуть исходный
вид» остаётся отдельной явной операцией. Помощник установленного меню работает
независимо: завершение GUI не удаляет пункт Umbrella.

SettingsWindowLifetime в app перехватывает Close, отклоняет уничтожение окна и
скрывает его. SettingsWindowControl в platform принимает два зарегистрированных
Win32-сообщения show/quit. Возврат видимости идёт через QWindow::show, чтобы QML
также видел изменение visible. Путь владельца окна проверяется перед обращением.
Открытие второго обычного экземпляра перенаправляется существующему окну до
создания нового Qt GUI/контроллера оформления. Диагностика, recovery и smoke
этим перенаправлением не затрагиваются.

Для скрытого QQuickView отключены persistent graphics/scene graph и вызывается
releaseResources; это запрос Qt на освобождение ресурсов, не измерение GPU-памяти.
Анимация главного экрана уже ограничена видимостью окна. Новых периодических
таймеров, сети или системной службы нет. Smoke закрывается обычным способом.

Перед обновлением/удалением установщик вызывает --quit-settings у MenuHost,
ждёт завершения GUI, затем останавливает помощника меню. Иначе скрытый GUI мог бы
держать установочные файлы и сеанс оформления. Ошибка завершения блокирует
обновление/удаление. Протокол геометрии, настройки островков/толщины и worker
восстановления не изменены.

Это сохранение применённого оформления в текущем сеансе Windows. Автоматическое
применение выбранного оформления после перезагрузки здесь не реализовано.
Аварийный выход GUI сохраняет прежнее восстановительное поведение.

## Проверки

Native DLL/host собраны MSVC x64. Test-MenuSettingsLaunch.ps1 подтвердил передачу
--settings, возврат к существующему скрытому тестовому владельцу через show,
его полное завершение через quit и повторный quit при отсутствии владельца.
Тестовый владелец не показывает GUI и не меняет системную панель.

settings_window_lifetime_tests.cpp проверяет реальный Close/QWindow, сохранение
event loop после закрытия, возврат того же окна, явный quit и обычное закрытие smoke.
Он добавлен в CTest, но локально не собран: полного Qt C++ SDK здесь нет.
Результаты Python-просмотра не подтверждают жизненный цикл полного C++ GUI.
Полное C++ GUI, фактическая экономия GPU при скрытии и installer/VM не проверены.

Актуальные результаты полной сборки: [VERIFICATION.md](VERIFICATION.md).
