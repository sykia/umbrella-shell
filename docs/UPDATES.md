# ADR-001: доверие обновлениям

Статус на 2026-10-19: **архитектурный план, runtime-интеграция отсутствует**.
Автообновления выключены. `--diagnostics` возвращает `updatesEnabled: false`.
Приложение не проверяет GitHub, не скачивает пакеты и не устанавливает обновления.

## Реализовано

`src/core/updates/UpdatePolicy.h` содержит только независимую политику:
отключённая интеграция запрещает установку; затем необходимы проверка пакета,
согласие пользователя и готовое восстановление. Stable отвергает draft/prerelease,
Beta отвергает draft. Булевы входы тестов не проверяют подписи и не подключены
к установщику. Наличие GitHub Release не меняет эту политику.

## Планируемая интеграция

Использовать WinSparkle с Ed25519 и стандартным HTTPS appcast; конкретная версия,
хеш зависимости и её лицензии должны быть проверены и закреплены перед подключением.
WinSparkle сейчас не скачан и не залинкован. Не писать собственные TLS,
криптографию или downloader. GitHub Releases JSON не является appcast.

Release pipeline должен сначала подписать installer, затем сформировать ленту
только из опубликованных совместимых assets. SHA-256 рядом с файлом — контроль
целостности, а не независимый корень доверия. Нужны встроенный доверенный
Ed25519 public key и отдельный защищённый private key для ленты/пакета.
Ключ из скачанного manifest доверенным не считается.

Перед исполнением необходимы Ed25519 и Authenticode через WinVerifyTrust
с проверкой доверенной цепочки, timestamp/revocation policy и допустимого издателя.
Возможность такой проверки до запуска через штатные точки расширения WinSparkle
ещё должна быть подтверждена. Неизвестный ключ/издатель, неверная подпись/размер,
TLS error и отсутствие recovery запрещают исполнение. Ключи и signing identity
не выдумываются и не хранятся в Git. Ротация/отзыв требуют отдельного плана.

Проверки должны быть отложенными и ограниченными по частоте, с backoff/jitter,
без службы и запроса при каждом старте. Stable/Beta требуют раздельных feeds и
определённой совместимости установки. Пользователь видит предложение и даёт
согласие; elevation и принудительное завершение Explorer не допускаются.
Ни feeds, ни UI обновления, ни эти runtime-проверки сейчас не реализованы.

## Блокирующее условие: installer engine и recovery

WinSparkle + in-place Inno не обеспечивают атомарность или восстановление после
потери питания. CloseApplications не является транзакцией. До runtime-интеграции
нужен ADR-002 с выбором проверенного installer engine (например MSI/WiX либо MSIX),
оценкой per-user/native-module совместимости и durable recovery. ADR-002 пока нет.

Контракт следующего этапа: сохранить предыдущий проверенный пакет, контролировать
место/конкурентную установку, использовать staging/commit/rollback движка,
держать состояние вне заменяемых файлов. После прерывания должен оставаться
согласованный комплект файлов. Успех installer и успешный запуск новой версии —
разные checkpoints; health check, ограниченные повторы, допустимый rollback и
security floor требуют отдельного протокола. Пользовательские настройки должны
сохраняться и оставаться совместимыми с разрешённой предыдущей версией.

Перед заменой native DLL нужно завершить GUI/worker/hosts с восстановлением
оформления и снятием hooks. Существующие StopMenuHelper/журнал taskbar не являются
транзакционным откатом установки. Explorer остаётся доступным; recovery может
запустить только системный Explorer по абсолютному пути, без замены оболочки.

## Обязательные испытания до включения

Подмена feed/payload, неизвестный издатель/ключ, истёкший сертификат с/без timestamp,
отмена/offline, disk full, locked DLL, concurrent setup, kill/reboot на каждой стадии,
повреждённый кэш, downgrade, падение новой версии и восстановление настроек.
Нужна чистая Windows 11 VM и документированные результаты. Матрица не выполнена.

До выполнения всех условий автообновления остаются отключёнными. Ручной
подписанный релиз и включение автообновлений — отдельные этапы.
