# Umbrella Dock

Dock — четвёртый вид Taskbar и отдельная страница Taskbar → Dock. Это собственные
Qt Quick окна в существующем процессе Umbrella, а не оформление окна Explorer.
Закрытие настроек оставляет Dock работающим. Логотип из assets открывает Umbrella;
его меню позволяет открыть настройки Dock, выключить Dock или завершить Umbrella.

## Совместимость и восстановление

Выбран совместимый режим: Dock **не скрывает** системный блок приложений.
Публичного стабильного API для скрытия только этого блока с сохранением Пуска,
трея и часов нет. Системная панель остаётся доступна; Dock размещается внутри
рабочей области поверх приложений, отдельно от зарезервированной панели Windows.
Дублирование приложений явно обозначено в настройках. Никаких новых внедрений,
изменений реестра Explorer, политик оболочки или завершения Explorer нет.

Dock не меняет appearanceProfilesV1, componentDraftsV1 и confirmedComponentV1.
Переключение обратно сохраняет прежнее нативное оформление. Сбой Dock оставляет
системную панель работающей; отдельный recovery-worker Dock не нужен.
Используются существующие mutex процесса и TaskbarRuntime::setLoginResume.
При `--resume-settings` учитывается `dock/enabled`, независимо от resumeAppearance.
Настройки в существующем пользовательском Taskbar INI вне установки. Выход
сохраняет выбор для входа в Windows; выключение Dock отключает только его режим.
Новых файлов вне существующего каталога программы для удаления нет.

Неудачная загрузка QML или графики выключает Dock, не затрагивая Explorer.
Временно недоступный путь/пакет сохраняется в собственных закреплениях; попытка
запуска возвращает ошибку, а не удаляет пользовательский выбор. Сохранение списка
ограничено 256 КиБ. startup-status учитывает включённый Dock наряду с native-session;
это отчёт восстановления при запуске, а не live-индикатор эксклюзивного управления.

## Приложения

WinEvent hooks OUTOFCONTEXT сообщают о создании, удалении, видимости, положении,
имени, минимизации и foreground. Одноразовый debounce объединяет события.
Снимки окон и извлечение значков выполняются последовательным worker-потоком,
который создаётся только при включении Dock. Постоянного сканирования процессов,
таймера кадров или отдельного D3D-устройства нет. Кэш ограничен 512 приложениями,
снимок — 512 окнами, закрепления — 128, настройки экранов — 16.

Модель группирует окна по AppUserModelID либо пути executable, сохраняет порядок
закреплений и стабильный порядок временных групп. Не отображаются невидимые,
cloaked, служебные/owned окна и окна собственного процесса. Группы доступны на
каждом Dock; меню указывает экран каждого окна. Изменение монитора окна приходит
через location-события. Это отображение всех окон, а не фильтрация по экрану.

ЛКМ запускает приложение без окон, восстанавливает/активирует окно, сворачивает
одно активное окно либо переключает следующее окно группы. Средняя кнопка запускает
новый экземпляр (single-instance приложение само решает, создавать ли его).
ПКМ открывает закрепление, порядок и выбор/закрытие конкретного окна.
Закрытие — WM_CLOSE, без принудительного завершения. Перед действиями проверяются
HWND, PID и время создания процесса; stale-запрос из меню отбрасывается.

Импорт читает доступные `.lnk` из пользовательского каталога TaskBar,
IShellLink и IPropertyStore; внутренний Taskband не читается/не изменяется.
Порядок ярлыков при импорте алфавитный; полный Windows pin-order и все packaged
закрепления этим не покрываются. Собственный порядок меняется перетаскиванием
закреплённых значков или командами меню. Можно добавить `.exe`, `.lnk`, `.appref-ms`
по пути и повторно импортировать отсутствующие закрепления без очистки собственного
списка. Есть сортировка по названию и сброс порядка к доступным ярлыкам Windows,
с сохранением собственных приложений. Packaged activation использует IApplicationActivationManager с AUMID;
ярлыки запускаются ShellExecute, сохраняя их аргументы. Не все приложения
публикуют пригодный AUMID. Для frame-hosted UWP идентичность извлекается из child
HWND packaged-процесса; имя и значок читаются из shell:AppsFolder. Packaged-закрепления
сохраняют AUMID, а не версионный путь WindowsApps. Можно вручную добавить
`shell:AppsFolder\AppUserModelID`. Реальные packaged-сценарии требуют desktop-проверки.

## Оформление и расположение

UISettings предоставляет системные цвета, accent, animations и advanced effects;
SPI_GETHIGHCONTRAST и GetSysColor обеспечивают непрозрачный high-contrast fallback.
WM_SETTINGCHANGE, WM_THEMECHANGED и WM_DWMCOLORIZATIONCOLORCHANGED обновляют тему.
Backdrop Dock использует документированный DwmSetWindowAttribute, с непрозрачным
fallback при недоступности или отключённой системной прозрачности.
Поверхность автоматически следует светлой/тёмной теме с лёгким accent-tint;
выделение использует accent. Тень рисуется без отдельного эффекта/промежуточной текстуры.
Точное воспроизведение внутреннего tint Taskbar Windows не заявляется.

Есть четыре стороны, три выравнивания, отступ, выбор экрана или отдельное окно на
каждом экране. Сторона/выравнивание/отступ сохраняются отдельно для выбранного
устойчивого ID из TaskbarRuntime (тот же hash monitorDevicePath, что у native-профилей).
Device name остаётся fallback при недоступном DisplayConfig. Геометрия вычисляется в DIP, ограничивается доступной рабочей областью
и пересчитывается по screen/geometry/DPI событиям. Недоступный выбранный экран
временно заменяется основным без удаления сохранённого выбора.

В режиме автоскрытия остаётся полоса ввода 3 DIP у физического края экрана;
остальная скрытая панель не блокирует мышь. Сначала завершается fade, затем HWND
сокращается до полосы. Есть задержки появления/скрытия,
скрытие при пересечении активным окном и полноэкранном окне. Открытое меню и
указатель удерживают Dock. Win32 physical rectangles переводятся относительно
исходного физического monitor RECT, а не смешиваются с глобальными Qt DIP.

Анимации Qt Quick ограничены изменениями/вводом, учитывают системный запрет
анимаций и пользовательскую скорость. Масштабирование изменяет размер ячейки,
учитывая соседние значки. При недостатке места список прокручивается.
Миниатюры включаются отдельной настройкой, по умолчанию выключены. После 500 мс
наведения создаётся собственное неактивирующее окно с максимум восемью DWM
thumbnail relationships. Можно выбрать или запросить закрытие конкретного окна;
остальные окна группы доступны в контекстном меню. Положение ограничивается
физической рабочей областью монитора, с учётом DPI и стороны Dock. Пока указатель
над preview, Dock не скрывается. При выходе, смене экрана/режима или отключении
все отношения, HWND и шрифт освобождаются. Нет PrintWindow, bitmap-capture,
таймера обновления изображений или нового D3D-устройства. При недоступном DWM
показывается заголовок окна; защищённый контент может оставаться пустым.
[Документированный контракт DWM](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmregisterthumbnail).
Живое превью использует тот же Dock.qml, отключая запуск и действия окон.
Изменения sliders записываются одним отложенным сохранением, без серии INI flush.

## Проверки и оставшаяся работа

`umbrella_dock_policy_tests` проверяет границы геометрии, отрицательные координаты,
разные логические размеры экранов, hide-policy и стабильный порядок/дедупликацию.
`umbrella_dock_fixture_tests` использует временный INI и offscreen Qt: закрепления,
порядок, группы окон, активность, исчезновение закрытого приложения, валидацию и
восстановление настроек, high contrast/reduced motion, загрузку реальных
Dock.qml/DockPage.qml без живого Explorer. Опциональный UMBRELLA_DOCK_FIXTURE_DIR
сохраняет горизонтальный светлый и вертикальный тёмный software-render снимки
с синтетическими приложениями. Это не проверка native D3D11/DWM.
`umbrella_dock_thumbnail_tests` подменяет только DWM API: проверяет переиспользование
отношения, освобождение при замене/сбросе/деструкторе, обработку отказов регистрации,
query/update, нулевой размер источника, aspect ratio и visibility flags. Настоящие
DWM relationships и desktop HWND этим тестом не создаются. Геометрия и hit-test
preview отдельно проверяются для 1–8 окон, маленьких рабочих областей, отрицательных
координат и DPI 100–400%. Добавлены регрессии стабильного обхода трёх окон после
смены Z-order, отсутствия лишних model notifications и повторного создания COM
apartment: перед RoUninitialize освобождается C++/WinRT factory cache этого модуля.
Ни один тест не запускает приложения и не отправляет сообщения настоящим окнам.

Локально выполнена прямая Release-сборка MSVC 14.42 / Qt 6.8.3 через существующий
Build-Local и адресная пересборка затронутых объектов. CMake presets/CTest этим
не заменяются и локально не запускались. Dock policy/model/QML fixtures прошли;
также прошли существующие offscreen Taskbar live/navigation проверки, включая
переход в Dock и обратно без лишних native-записей. Горизонтальный и вертикальный
software-render снимки просмотрены. Foundation и аудит staged index выполнены.

Development output развёрнут локально windeployqt без установки и без проверки
installer. Qt translations в этом выводе не проверены; все собственные подписи
Dock заданы по-русски. Полный GUI/D3D11 smoke по-прежнему требует отдельного запуска.
Для offscreen fixture после windeployqt нужен `platforms/qoffscreen.dll` из того же
Qt SDK либо QT_QPA_PLATFORM_PLUGIN_PATH: обычный GUI deployment включает qwindows,
но не тестовую платформу offscreen.

Обязательная контролируемая интеграционная проверка после объединения веток:
два экрана 2560×1440, mixed DPI/смена primary/hotplug, реальные Win32 и packaged
приложения, системная смена темы/high contrast, полноэкранные игры, reboot/login,
перезапуск Explorer и установка/удаление. Во время параллельной разработки эти
desktop-сценарии запрещены и не заявляются проверенными.

CPU/RAM/GPU в простое, при наведении и большом числе настоящих окон ещё не
измерены. Отсутствие polling — свойство реализации, а не доказательство отсутствия
нагрузки. Shell API извлечения значков не предоставляет timeout; его задержки
и завершение worker требуют измерений на реальной конфигурации.

Синтетический замер 2026-10-21: `umbrella_dock_fixture_tests --benchmark`, 512 окон
в 64 группах, 100 обновлений. Среднее reconcile до оптимизации — 2,513 мс, после —
1,475 мс; убраны промежуточные QVariant-списки и ненужные icon notifications.
После оптимизации весь процесс этого model-only теста: working set 22,29 MiB,
private bytes 5,61 MiB; за 999 мс ожидания зарегистрировано 0 мс CPU. Это один
синтетический замер без WinEvent discovery, QML-окон, DWM и D3D11, а не показатели
настоящего Dock и не гарантия нулевой нагрузки. Benchmark запускается отдельно
от functional fixtures и не участвует в обычном CTest.

Общие точки интеграции: CMakeLists.txt, main.cpp, Settings.qml, TaskbarPage.qml и
scripts/Build-Local.ps1, а также тест tests/taskbar_live_ui_test.py. TaskbarSettings
и TaskbarRuntime API не изменены.
Новый context property `dockSystem` принадлежит composition root. Режим Dock
должен сохранять его владение до уничтожения Dock-окон. Для Settings Blur признак
`dockSystem.enabled` означает совместимый Dock, **не** эксклюзивное управление
системной панелью. Нативное управление определяется существующей native-session.
