# Shell Bar: решение и проверка

Статус на 2026-10-17: дальнейшие сборки, тесты и GUI-запуски отложены по запросу
владельца. Последние изменения закрепления панели, drag-and-drop и групп окон
ещё не подтверждены на двух мониторах Windows 11. Матрица ниже — план испытаний.

## Текущий интерфейс

Светлая панель 36 DIP поддерживает четыре края, SVG-иконки, логотип Umbrella,
группы окон, раскладку и открытие параметров звука. Настройки 680×440 имеют
красный акцент и анимации; логотип показывает/скрывает окно. Подсказки поверх
кнопок удалены. Модули переносятся между горизонтальными зонами слева/центр/справа.

Пять кружков — собственные группы окон каждого монитора, не виртуальные столы
Windows. Активная группа красная, заполненность означает наличие окон.
Системные бинды не меняются. Группы не сохраняются между запусками. Лимиты —
16 мониторов и 256 обычных окон; owned/tool/elevated/cloaked исключены.
Обход раз в 500 мс работает только при активном модуле; повторный показ окна
приложением может быть заметен до очередного обхода.

Панель закрепляется на физическом краю отдельно от согласования AppBar;
fullscreen снижает z-order после проверки foreground окна. Результат этого
изменения требует проверки исчезновения и перемещения панели на рабочем столе.

## Подавление панели Windows

AppBar резервирует рабочую область, auto-hide освобождает системную область,
а TaskbarVisibility скрывает все проверенные окна панелей Explorer через
ShowWindow(SW_HIDE). WINEVENT_OUTOFCONTEXT уведомляет guard о создании, показе и
изменении геометрии. Guard не внедряет код в Explorer и не завершает его.

Ограничение: Shell_TrayWnd / Shell_SecondaryTrayWnd — детали реализации Explorer,
не поддерживаемый Microsoft API замены taskbar. Асинхронный hook подавляет
повторный показ после получения события, а не до первого возможного кадра.
Не заявляется абсолютное отсутствие вспышек на всех версиях Windows или при
перезапуске Explorer. Проверка на конкретной Windows 11 обязательна.
`--taskbar-status` возвращает видимость/геометрию всех обнаруженных taskbar окон.
Если механизм не распознаёт панель, он не является подтверждённым полным скрытием.

Источники API:
- [Application desktop toolbars](https://learn.microsoft.com/en-us/windows/win32/shell/application-desktop-toolbars)
- [SHAppBarMessage](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shappbarmessage)
- [Qt Quick QQuickWindow](https://doc.qt.io/qt-6.8/qquickwindow.html)

## Автоматические проверки

CTest: guard stop event, смерть синтетического родителя, оба исходных режима,
ошибка восстановления и ошибки открытия handles (через подмену операции восстановления,
без изменения реального рабочего стола); политика обновлений, diagnostics без GPU, неизвестные CLI аргументы,
отклонение неверных guard аргументов, загрузка обоих QML-экранов/PNG и первый
кадр D3D11 (`--ui-smoke`). Deployment smoke повторяет загрузку из stage без
Qt development PATH. Ни один из этих тестов не включает замену панели Windows.

Smoke выводит workingSetBytes и число кадров. При заданном UMBRELLA_SMOKE_DIR
последовательно сохраняются панель и четыре страницы настроек. Это ориентир
памяти тестового процесса с двумя окнами, не измерение стабильного idle UI
и не бюджет RAM для нескольких мониторов. Локальные CPU/GPU/idle RAM замеры
и ручная Windows 11 VM-матрица пока не выполнены.

## Обязательная ручная матрица перед распространением

В исходниках также есть тест конфигурации и новый fixture групп: discovery
ограничен PID синтетического дочернего окна. Наличие теста не означает его
подтверждённого прохождения. Дополнительно проверить перенос каждого модуля,
отмену drop, сохранение зон, красную тему и отсутствие подсказок. На двух мониторах
проверить независимость групп, заполненность и возврат скрытых окон при отключении
модуля, смене края, выходе, Ctrl+Alt+U и смерти только GUI при живом guard.

В Windows 11 VM со snapshot проверить и записать build Windows, драйвер, Qt,
число мониторов, DPI и исходный флаг auto-hide:

1. Первый запуск, видимость кадра до автоскрытия, логотип и настройки с обеих панелей.
2. Один/два/три монитора, primary change, отрицательные координаты, 100/150/200% DPI,
   hot plug, разрешение, RDP connect/disconnect, sleep/wake и перезапуск Explorer.
3. Maximized и fullscreen apps: корректная рабочая область, отсутствие перекрытия.
4. Отключение/включение замены, обычный выход, Ctrl+Alt+U и занятое сочетание.
5. Исходный auto-hide on/off: принудительно завершить только GUI, затем только guard;
   убедиться в восстановлении исходного флага и отсутствии зависшей рабочей области.
6. Завершить оба процесса: recovery command и последующий запуск с журналом.
7. Установка, предложение запуска, opt-in автозапуск после logon, upgrade/uninstall
   при открытых окнах, сохранность настроек и отсутствие Run после uninstall.
8. Ошибки записи настроек, блокировка запуска guard, ошибка графики, второй экземпляр.
9. Idle 60 секунд после прогрева: CPU time обоих процессов, working/private bytes,
   GPU engine utilization и число Present. Повторить с открытыми настройками и
   разным числом мониторов; фиксировать реальные результаты, не обещать нулевой GPU.

Процесс восстановления покрывает смерть GUI, но не его зависание; recovery event
можно подать из отдельного CLI. После одновременного отказа guard и GUI следующий
запуск или recovery command восстанавливает taskbar, но не гарантирует возврат
скрытых приложений: их снимок находится только в общей памяти этих процессов.
Пункт 6 матрицы проверяет именно taskbar. Это не служба восстановления Windows.
