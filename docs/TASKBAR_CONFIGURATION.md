# Конструктор в настройках Taskbar

Конфигурация редактируется в окне Umbrella. На системной панели GUI не включает
режим drag. Карточки обозначают оригинальные компоненты Explorer; они не создают
новых кнопок Windows. Это работающий GUI с узким нативным применением, не полный
редактор всех системных контролов.

## Использование

### Незавершённый этап Taskbar Reorder — 20 октября 2026

Продолжение второго этапа: общий core-planner рассчитывает несколько групп в
Left/Center/Right, используя фактическую ширину и независимую геометрию монитора.
Порядок задания определяет порядок в области; apps сохраняет внутренние offsets
всех текущих экземпляров. Условный отсутствующий компонент не создаётся;
неподвижные peers и tray-препятствия участвуют в проверке столкновений.
Ошибочный план не возвращает готовых записей. Лимит — 64 объекта, 64 препятствия,
gap 0…96 DIP, проверка столкновений O(n²), без сканирования XAML во время drag.

Действующий native Task View подключён к общей adapter-транзакции:
проверка идентичности/родителя и текущей геометрии всех объектов → запись →
проверка фактических позиций/hit-test/пересечений → ack. Отказавший setter считается
потенциально частично завершённым; откат включает его и продолжается при отказе
другого объекта. Неизменная геометрия не переписывается, но проверяется перед ack.
Проверка ID Task View защищает от использования переработанного repeater-контейнера.

Fixture проверяет несколько ролей/областей, рост/сокращение apps, независимые размеры
двух мониторов, ambiguous/unsupported/missing peers, stale/unloaded объекты,
частично записавший и бросивший исключение setter, проигнорированную запись,
отказ verify и неудачный rollback. Это тест общего механизма на adapters-mocks;
перенос нескольких оригинальных компонентов Explorer этим не подтверждён.

Добавлены fail-closed проверки конечности координат, границ и столкновений и
проверка фактического TransformBounds после native-записи перед подтверждением.
Инвалидированная привязка снимается и пересоздаётся один раз по следующему запросу.
Если повторное применение прежней позиции после отказа не удалось, её
confirmedComponentV1 удаляется; исторический черновик и appearance-профили остаются.
Смена монитора отменяет ожидающий debounce/drop. Ответ taskview-refused немедленно
прерывает ожидание вместо исчерпания трёхсекундного таймаута.

`UmbrellaTaskbarHost.exe --inspect-components` через существующую hook-сессию читает
до 512 узлов и 48 записей на панель, включая SystemTray в том же XamlRoot:
роль, класс, непосредственный visual parent, текущий RECT в DIP, visibility/hit-test.
Запрос не меняет свойства XAML и не запускает drag. Неполный обход возвращает отказ,
а не полный каталог. Неизвестные классы/условные элементы могут отсутствовать.
Apps — общая роль экземпляров, не устойчивый ID приложения. Quick Settings
обнаруживается целиком; сеть/звук не выдаются за независимо перемещаемые объекты.
Точные DLL gates сохранены. Диагностическая hook-сессия несовместима с другим
активным native-owner. Команда пока не проверена на настоящем Explorer.

**Полноценная перестановка ещё не реализована.** GUI по-прежнему применяет только
проверенный ранее сценарий Task View. Новые геометрические проверки/перепривязка
собираются и проверяются изолированно; сохранение кликов/flyout на рабочем столе
после этих изменений требует отдельной контролируемой проверки.

Продолжение: в независимой desktop/VM-сессии получить новый снимок двух панелей,
подтвердить functional wrappers и владельцев layout/model. Затем реализовать
адаптер порядка ItemsRepeater с task-list model и отдельный адаптер SystemTray;
проверить клавиатурный порядок, flyout, динамику приложений, DPI и owner-death.
Только после этого расширять capability и GUI-drop. Сохранять существующие
componentDraftsV1/confirmedComponentV1 и TaskbarRuntime; Dock должен завершать
component-session перед захватом оформления, не удаляя native-профиль Reorder.

Проверки этапа: полная прямая сборка GUI, native DLL/host и fixtures через
Build-Local.ps1 (MSVC 14.42, Qt 6.8.3); отдельная сборка нового mock-host IPC test.
Прошли portable placement/registry tests, IPC ack/refusal/error без Explorer,
policy/menu-patch tests, geometry fixture с собственным тестовым HWND,
settings lifetime, diagnostics и обе PySide6 QML-проверки. Новый QML-сценарий
проверяет отмену ожидающей команды при смене монитора. QML warnings отсутствуют.
Реальный Taskbar/desktop не изменялся; CMake presets, installer/VM, клики/flyout,
ресурсы Explorer и native apply latency в этой сессии не проверялись/не измерялись.
IPC test проверяет ответ раньше 1500 мс при открытом stdout mock-child; это
проверка отсутствия прежнего 3000-мс ожидания отказа, не benchmark Explorer.

1. Раскройте **Taskbar** в боковом меню и выберите **«Конфигурация панели»**.
   Оформление панели остаётся на отдельной странице **«Основные настройки»**.
2. Выберите монитор компактной кнопкой вверху страницы. Переключение ничего
   не применяет и не изменяет другой монитор.
3. На основном экране перетащите **«Представление задач»** в область **«Слева»**,
   сразу после **«Виджетов»**. Источник освобождает место, допустимая вставка
   подсвечивается. Escape и отпускание вне области отменяют перенос.
4. После отпускания одноразовый debounce 180 мс отправляет последнюю конфигурацию
   в существующий native-host. Только подтверждённое положение становится моделью
   страницы и сохраняется. Изменение расстояния после размещения также применяется
   автоматически. Пока native-owner занят, последнее изменение ждёт его завершения.
5. **«Восстановить»** снимает смещение через существующий откат и удаляет сохранённую
   конфигурацию выбранного монитора. Другие мониторные записи остаются. Отказ
   восстановления не выдаётся за успех; ошибка записи настроек сообщается отдельно.

Кнопки «Применить», «Вернуть Task View» и сохранения произвольного черновика больше
нет. Неподдерживаемые компоненты не начинают drag; подсказка кратко объясняет причину.
У Task View неподдерживаемый drop не меняет конфигурацию и не сохраняет её.
На дополнительном мониторе перенос пока отключён целиком: нативная поддержка
второй панели не подтверждена. Каталог не является текущим сканированием видимости
системных компонентов и не создаёт копий кнопок Explorer.

Условия native-применения: исходная нижняя панель полной ширины 48 DIP, DPI 100%,
без автоскрытия и другой активной сессии оформления; точные системные DLL должны
совпасть с gate. При отказе команды backend пытается вернуть предыдущее подтверждённое
смещение. Если восстановить его не удалось, интерфейс не продолжает показывать его
как подтверждённое. Изменение общего оформления предварительно закрывает component-session.

## Модель, сохранение и восстановление

- `Settings.qml` использует существующие sidebar и переходы по opacity. Подпункты
  раскрываются с анимацией высоты; активная страница выделяется. Конструктор имеет
  собственный ScrollView и передаёт его Flickable для автопрокрутки захваченного drag.
- `TaskbarLayout.js`: version=1, четыре массива available/left/center/right и gap
  0…96 DIP. Проверяются уникальность ID и допустимые индексы. Схема допускает будущие
  адаптеры, но GUI и C++ сейчас разрешают только точную проверенную перестановку Task View.
- `TaskbarSettings`: `activeComponentConfiguration` обозначает подтверждение в этом
  сеансе, а не просто прочитанную запись. Сначала native-ack, затем сохранение.
  `componentDraftsV1` хранит независимые записи мониторов в пользовательском INI;
  максимум 16 записей, 64 KiB JSON и 64 ID на запись. Старые произвольные черновики
  не превращаются в применённую конфигурацию.
- Идентификация берётся из общего `TaskbarRuntime::monitors()`: SHA-256 системного
  monitorDevicePath из QueryDisplayConfig. Номер DISPLAY и порядок перечисления
  не являются ключами профилей. Доступность основной панели проверяется по тому же
  runtime-списку, без второго сопоставления через QScreen.
- Отдельная `confirmedComponentV1` разрешает повторное применение только сценария,
  ранее подтверждённого native-host. Composition root/runtime выполняет его при
  запуске; одно чтение страницы ничего не применяет. Это совместная интеграция
  с механизмом [автовосстановления](STARTUP_RECOVERY.md). Повторный экземпляр модели
  проверен; настоящий повторный вход в Windows в этом этапе не выполнялся.
- `TaskbarModuleSession`: прежний QProcess/native-host путь `--configure-taskview`;
  EOF/обычный выход завершают сессию с откатом. GUI-путь не регистрирует pointer-drag
  на системной панели и не отключает IsHitTestVisible.

Нативная команда after-widgets получает **текущую** правую границу единственного
Taskbar.AugmentedEntryPointButton в том же TaskbarFrameRepeater, добавляет gap и
меняет Translation оригинальной Task View. Найденный текущий wrapper шире peer
из исторического UIA-каталога: 216 DIP вместо 152. Поэтому координаты старого
снимка не используются как доказательство свободного места. Проверяются текущие
границы, родитель и пересечения. Отказ возвращается в GUI; ошибочная операция
завершает host с запросом отката. Другие сценарии остаются отключены в GUI.

Исходная Translation сохраняется до первой записи. Unloaded, несовместимая
перестройка/пересечение, Reset, выход и смерть host возвращают исходное состояние.
Новое значение другого владельца не затирается. При смене оформления сначала
завершается сессия компонента; активная другая native-сессия отклоняет подключение.
Факт применения подтверждается один раз; автоматическое восстановление при
последующей перестройке не означает постоянного удержания пользовательской схемы.
Зависший Explorer, одновременный сбой восстановительных процессов и потеря
питания по-прежнему вне гарантии. Логический порядок/Tab-порядок и исходный
layout-slot ItemsRepeater не меняются. Межконтейнерного переноса нет.

## Проверки автоматического применения — 20 октября 2026

- PySide6 6.8.3, реальные Qt mouse events: допустимый drag/drop, запрет drag остальных
  компонентов, отказ неподдерживаемой позиции, debounce, очередь занятого владельца,
  отказ без сохранения, изоляция двух мониторов, отказ/успех восстановления и Escape.
  Автопрокрутка захваченного drag проверена в ScrollView высотой 560. QML warnings нет.
- Настоящий `Settings.qml`: загрузка/анимация, раскрытие Taskbar, переход между двумя
  страницами, кнопки мониторов, раскладка при 1000×700 и 800×560; без записей Windows.
  В видимом проверочном окне через computer-use также проверен перенос карточки;
  его backend тестовый. Реальное применение проверено отдельно сквозным fixture ниже.
- MSVC 14.42 / Qt 6.8.3: свежая прямая сборка GUI/native/fixtures через Build-Local.ps1.
  Полный CMake/installer/VM цикл этого этапа не выполнялся.
- C++/Qt → TaskbarSettings → QProcess → Explorer: отпускание карточки автоматически
  переместило оригинальную Task View с x=1239 на x=224 (Widgets wrapper 216 + gap 8).
  UIA CompareElements/ElementFromPoint и WindowFromPoint подтвердили исходный элемент
  и системную панель; физический клик открыл Task View. Восстановление вернуло RECT.
  Сохранение/повторное чтение, две мониторные записи, запрет неверного gap/перестановки
  и повторное применение подтверждённой схемы новым владельцем прошли.
- Fixture перенаправляет HKCU через RegOverridePredefKey в временную тестовую ветку:
  настоящий Run/UmbrellaShell не переписывается; INI находится во временном каталоге.
- Принудительно завершён только свежий тестовый native-host: исходные x=1239 и native
  hit-test восстановились. Explorer и работающие пользовательские процессы не завершались.
  Совместная смерть всех восстановительных процессов не проверялась.

Воспроизведение без изменения Windows:

```powershell
python tests/taskbar_configuration_ui_test.py
python tests/taskbar_navigation_ui_test.py
```

Сквозные тесты изменяют настоящую Task View; команды приведены ниже. Они не запускаются
в CTest/CI. Для native-проверок нужны совместимые DLL и отсутствие другой сессии оформления.

## Исторические проверки — 19 октября 2026

Следующие наблюдения относятся к прежнему редактору черновиков с отдельной кнопкой
применения. Они сохранены как история и не описывают текущий пользовательский поток.


- PySide6 6.8.3: Qt-события мыши, перенос из каталога/обратно, пустая область,
  произвольная вставка, обе стороны перестановки, Escape/неверный drop,
  независимость мониторов, блокировка неподдерживаемого применения,
  отказ сброса и автопрокрутка реальной страницы при высоте 560. Без QML warnings.
- Сквозной C++/Qt desktop fixture: реальные два QScreen, отдельное сохранение и
  повторная загрузка черновиков, отклонение неверного gap; тестовый INI находится
  во временном каталоге. Qt drag → кнопка применения → TaskbarSettings → QProcess
  → Explorer: та же исходная Task View перемещена на x=224 (граница 216 + gap 8).
  UIA CompareElements/ElementFromPoint подтвердили оригинал, штатный физический
  клик открыл Task View. Сброс вернул исходный RECT. Черновой drag не менял Windows.
- Отдельная native-проверка координатной команды: x=1239 → 250, оригинальный
  hit-test/Click, Task View, фокус и Reset. Без drag на системной панели.
- Свежий host после after-widgets принудительно завершён: через 1,5 s исходные
  x=1239 и native hit-test восстановлены. Explorer не завершался/не перезапускался.
- GUI, native host/DLL и fixture собраны точечно MSVC 14.42 / Qt 6.8.3; UI smoke
  показал D3D11/blur/кадры без QML warnings. Локальная GUI-сборка использовала /MT
  и ресурсы rcc; полный CMake/deployment/installer/VM цикл этого этапа не выполнен.

Воспроизведение (desktop-проверки меняют настоящую Task View, не запускать в CI):

```powershell
python tests/taskbar_configuration_ui_test.py # PySide6 6.8.3
cmake --build --preset release --target umbrella_configuration_desktop_test
# Fixture, host и matching module должны быть рядом; требуется Qt runtime.
./scripts/Test-TaskbarConfiguration.ps1 -HostPath <host.exe> -FixturePath <fixture.exe>
./scripts/Test-TaskbarConfiguration.ps1 -HostPath <host.exe> -OwnerDeath
# Без FixturePath проверяется native placement/click/focus/reset, а не GUI.
```

Для полной реализации ещё нужны подтверждённые адаптеры остальных контейнеров,
проверка логического порядка, динамических приложений и tray icons, flyout-якорей,
состава/скрытия, дополнительной панели, иных DPI/версий DLL и сочетаний оформления.
Это не обещание свободной перестановки всех контролов уже сейчас.

## Закрытие этапа: обычная локальная сборка

Проверен запуск обычного UmbrellaShell.exe без тестовых аргументов и без
переменных Qt SDK: В прежнем GUI Taskbar в левой колонке открывал «Конфигурация панели»
в верхней части общей страницы, перед предпросмотром оформления. Сейчас это отдельный подпункт. Подтверждены видимые
каталог, выбор монитора и три области. Применение к Windows при этой проверке
не запускалось; установленная версия не заменялась.

Локальная Windows GUI-сборка повторно собрана MSVC/Qt 6.8.3, Qt runtime развёрнут
рядом с exe в игнорируемом tmp/configuration-prototype. Её можно запустить
отдельно от установки. Это проверочная сборка без нового installer;
полная CMake/deployment-проверка CI и VM по-прежнему не выполнена.
