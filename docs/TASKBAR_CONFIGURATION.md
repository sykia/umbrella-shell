# Конструктор в настройках Taskbar

Конфигурация редактируется в окне Umbrella. На системной панели GUI не включает
режим drag. Карточки обозначают оригинальные компоненты Explorer; они не создают
новых кнопок Windows. Это работающий GUI с узким нативным применением, не полный
редактор всех системных контролов.

## Использование

1. Откройте Taskbar → «Конфигурация панели», выберите монитор.
2. Перетащите карточки между каталогом и областями «Слева», «По центру», «Справа».
   Порядок сверху вниз внутри области задаёт желаемый порядок слева направо.
   Можно вставлять между любыми карточками; источник освобождает место,
   маркер показывает вставку. У края страницы работает автопрокрутка.
   Escape или отпускание вне области отменяет перенос.
3. Расстояние задаётся отдельно для каждого монитора. Черновик сохраняется
   после завершённого изменения. Открытие/переключение монитора ничего
   автоматически не применяет к Explorer.
4. Для проверенного сценария разместите слева «Виджеты», затем
   «Представление задач». Нажмите **«Применить только Task View»**.
   Остальные изменения черновика не применяются. Доступен только основной
   монитор, исходная нижняя панель полной ширины 48 DIP, DPI 100%, без
   автоскрытия и активной сессии оформления. DLL должны точно совпасть с gate.
5. **«Вернуть Task View»** снимает нативное смещение. **«Сброс»** также возвращает
   черновик выбранного монитора к базовому расположению каталога. При отказе
   восстановления черновик не сбрасывается. Остальные мониторные черновики
   сохраняются; сброс дополнительного монитора не завершает нативную сессию
   основного. Стандартные настройки Windows не переписываются.

Возврат карточки в каталог означает исключение из желаемого состава, **не скрытие
системной кнопки**. На дополнительном мониторе пока редактируется только черновик.
Другие позиции Task View и все остальные компоненты помечены неподдерживаемыми.
«Часы и дата», группа приложений и подобные составные элементы представлены
едиными функциональными карточками. Внутренние glyph, progress/overlay, фон,
служебные HWND и закрытые flyout не превращаются в независимые компоненты.
Условные компоненты и отсутствовавшие на конкретной панели отмечены отдельно;
каталог основан на исследовании, а не объявляется текущим live-снимком.

## Разделение модели и применения

- `TaskbarLayout.js`: каталог из исследования, version=1, массивы available/left/
  center/right, gap=0…96 DIP, проверка уникальности и атомарное перемещение.
  Индекс вставки считается после удаления источника. Неподдерживаемые
  компоненты редактируются в модели, но не отправляются на нативное применение.
- `TaskbarConfiguration.qml`: захват мыши только в настройках, анимации,
  вставка, выбор монитора, явное применение и статусы. Отмена не меняет модель.
- `TaskbarSettings`: отдельные сохранённые черновики по имени экрана и, когда
  доступен, серийному идентификатору QScreen. Значения остаются в существующем
  пользовательском INI, вне установки: componentDraftsV1. Максимум 16 записей,
  64 KiB JSON, 64 ID на черновик; дубликаты/неверные значения отклоняются.
  Сменившаяся идентичность экрана получает базовый черновик. Нет автоприменения.
- `TaskbarModuleSession`: существующий QProcess/native-host путь,
  opt-in `--configure-taskview`, EOF/обычный выход завершают сессию с откатом.
- `TaskbarModule`/`button_edit::Session`: свойства меняются на UI-потоке Explorer
  с прежним владельцем и worker восстановления. GUI-путь не регистрирует
  PointerPressed/Moved/Released и не отключает IsHitTestVisible.

Нативная команда after-widgets получает **текущую** правую границу единственного
Taskbar.AugmentedEntryPointButton в том же TaskbarFrameRepeater, добавляет gap и
меняет Translation оригинальной Task View. Найденный текущий wrapper шире peer
из исторического UIA-каталога: 216 DIP вместо 152. Поэтому координаты старого
снимка не используются как доказательство свободного места. Проверяются текущие
границы, родитель и пересечения. Отказ возвращается в GUI; ошибочная операция
завершает host с запросом отката. Другие сценарии остаются отключены в GUI.

Исходная Translation сохраняется до первой записи. Unloaded, несовместимая
перестройка/пересечение, Reset, выход и смерть host возвращают исходное состояние.
Новое значение другого владельца не затирается. При смене оформления сначала
завершается сессия компонента; активная другая native-сессия отклоняет подключение.
Факт применения подтверждается один раз; автоматическое восстановление при
последующей перестройке не означает постоянного удержания пользовательской схемы.
Зависший Explorer, одновременный сбой восстановительных процессов и потеря
питания по-прежнему вне гарантии. Логический порядок/Tab-порядок и исходный
layout-slot ItemsRepeater не меняются. Межконтейнерного переноса нет.

## Фактические проверки — 19 октября 2026

- PySide6 6.8.3: Qt-события мыши, перенос из каталога/обратно, пустая область,
  произвольная вставка, обе стороны перестановки, Escape/неверный drop,
  независимость мониторов, блокировка неподдерживаемого применения,
  отказ сброса и автопрокрутка реальной страницы при высоте 560. Без QML warnings.
- Сквозной C++/Qt desktop fixture: реальные два QScreen, отдельное сохранение и
  повторная загрузка черновиков, отклонение неверного gap; тестовый INI находится
  во временном каталоге. Qt drag → кнопка применения → TaskbarSettings → QProcess
  → Explorer: та же исходная Task View перемещена на x=224 (граница 216 + gap 8).
  UIA CompareElements/ElementFromPoint подтвердили оригинал, штатный физический
  клик открыл Task View. Сброс вернул исходный RECT. Черновой drag не менял Windows.
- Отдельная native-проверка координатной команды: x=1239 → 250, оригинальный
  hit-test/Click, Task View, фокус и Reset. Без drag на системной панели.
- Свежий host после after-widgets принудительно завершён: через 1,5 s исходные
  x=1239 и native hit-test восстановлены. Explorer не завершался/не перезапускался.
- GUI, native host/DLL и fixture собраны точечно MSVC 14.42 / Qt 6.8.3; UI smoke
  показал D3D11/blur/кадры без QML warnings. Локальная GUI-сборка использовала /MT
  и ресурсы rcc; полный CMake/deployment/installer/VM цикл этого этапа не выполнен.

Воспроизведение (desktop-проверки меняют настоящую Task View, не запускать в CI):

```powershell
python tests/taskbar_configuration_ui_test.py # PySide6 6.8.3
cmake --build --preset release --target umbrella_configuration_desktop_test
# Fixture, host и matching module должны быть рядом; требуется Qt runtime.
./scripts/Test-TaskbarConfiguration.ps1 -HostPath <host.exe> -FixturePath <fixture.exe>
./scripts/Test-TaskbarConfiguration.ps1 -HostPath <host.exe> -OwnerDeath
# Без FixturePath проверяется native placement/click/focus/reset, а не GUI.
```

Для полной реализации ещё нужны подтверждённые адаптеры остальных контейнеров,
проверка логического порядка, динамических приложений и tray icons, flyout-якорей,
состава/скрытия, дополнительной панели, иных DPI/версий DLL и сочетаний оформления.
Это не обещание свободной перестановки всех контролов уже сейчас.

## Закрытие этапа: обычная локальная сборка

Проверен запуск обычного UmbrellaShell.exe без тестовых аргументов и без
переменных Qt SDK: Taskbar в левой колонке открывает «Конфигурация панели»
в верхней части страницы, перед предпросмотром оформления. Подтверждены видимые
каталог, выбор монитора и три области. Применение к Windows при этой проверке
не запускалось; установленная версия не заменялась.

Локальная Windows GUI-сборка повторно собрана MSVC/Qt 6.8.3, Qt runtime развёрнут
рядом с exe в игнорируемом tmp/configuration-prototype. Её можно запустить
отдельно от установки. Это проверочная сборка без нового installer;
полная CMake/deployment-проверка CI и VM по-прежнему не выполнена.
