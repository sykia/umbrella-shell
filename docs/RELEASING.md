# Сборки и публикация

Репозиторий: [sykia/umbrella-shell](https://github.com/sykia/umbrella-shell).
Состояние проверок смотрите во вкладке Actions. Публикация исходников не означает
наличие подписанного бинарного релиза: он требует отдельного тега и сертификата.
Секреты и сертификаты в исходники не входят.

На 2026-10-17 дальнейшие сборки, тесты и GUI-запуски отложены по запросу владельца.
Текущая публикация документации не создаёт бинарный релиз или тег и не подтверждает
работу последних изменений на Windows 11. Runtime и снимки QML из CI не заменяют
ручную проверку двух мониторов.

`ci.yml`: Windows x64 Qt 6.8.3 / MSVC, CTest, Qt deployment, unsigned Inno exe,
запуск deployed host с очищенным PATH. Отдельно Linux проверяет независимость
core от Qt/Windows. CI не устанавливает пакет в пользовательскую систему.

`release.yml`: push тега `v0.1.0` (строго совпадает с CMake), environment `release`,
сборка и тесты, подпись exe/uninstaller/setup, проверка Authenticode, SHA-256,
публикация assets через GitHub Releases. Не выпускает appcast и не включает
обновления. При отсутствии секретов публикация закрыта ошибкой.

## Подключение репозитория

1. Клонировать репозиторий, проверить remote и запустить CI. Перед отправкой
   изменений выполнить `scripts/Test-PublicRepository.ps1` для staged index.
2. Создать environment `release`, ограничить теги/ветки, включить required
   reviewers для доступа к signing secrets. Подпись не доступна PR workflow.
3. Для подготовленного PFX-пути задать `WINDOWS_CERTIFICATE_BASE64` и
   `WINDOWS_CERTIFICATE_PASSWORD` в environment. Нужен доверенный code-signing
   сертификат с приватным ключом. EV/hardware/cloud-only ключи этим PFX-путём
   не поддерживаются: заменить signing adapter на провайдера/HSM.
4. GitHub Actions закреплены на проверенные полные commit SHA. При обновлении
   сверять SHA с upstream и проверять изменения. Проверить условия Qt, Inno
   и всех поставляемых runtime DLL; добавить
   фактические license texts и SBOM. Это gate перед публичной поставкой.
5. Прогнать VM-матрицу ниже, затем изменить версию в CMake и выпустить тег.
   Повторная публикация того же тега должна завершаться ошибкой, assets
   существующего релиза не перезаписываются.

Секрет PFX существует только во временном каталоге runner на время импорта;
файл удаляется finally, сертификат удаляется в always step. Windows SDK
signtool использует сертификат в CurrentUser store, SHA-256 и RFC3161 timestamp.
Пароль не передаётся signtool в командной строке. Сторонние Qt DLL сохраняют
свои исходные подписи. До публикации проверить всю dependency closure.

## Обязательная ручная VM-проверка установщика

- Чистая Windows 11 x64 без Qt/MSVC SDK, обычная учётная запись.
- Установка без UAC в пользовательский каталог, diagnostics запускается.
- Путь с пробелами/кириллицей; Explorer работает до/после установки.
- Повторная установка той же версии; новая версия поверх старой; занятые файлы.
- Отмена на шагах wizard, отсутствие частичного продукта после ошибки.
- Удаление из Settings, ярлыки удалены, Explorer и пользовательские настройки сохранены, Run удалён, taskbar восстановлена.
- Проверить подписи setup, installed exe и uninstaller.
- При upgrade/uninstall вернуть скрытые приложения до остановки GUI/guard.
  Проверить сохранение края/зон модулей и отсутствие переназначения системных
  сочетаний. Двойной сбой GUI/guard не покрывается снимком групп.
- На signed build проверять предупреждения SmartScreen отдельно: подпись
  не гарантирует репутацию или отсутствие предупреждений.

Выполнение этой матрицы не утверждается. Успешная Inno-компиляция в CI
не заменяет установку/удаление в чистой Windows 11 VM. Предварительные сборки
не являются доказательством готовности обновлений к эксплуатации.

Перед распространением Shell Bar дополнительно выполнить [матрицу панелей](SHELL_BAR.md).

## Подтверждённые проверки

В [CI от 2026-10-17](https://github.com/sykia/umbrella-shell/actions/runs/39036764911)
для коммита `7bf5407` успешно выполнены:

- Linux: сборка независимого core и тест политики обновлений.
- Windows Server 2022 runner: MSVC/Qt-сборка, все три CTest-проверки,
  Qt deployment и компиляция unsigned Inno installer.
- Запуск deployed host с PATH, содержащим только системные каталоги,
  и без QT_PLUGIN_PATH/QML2_IMPORT_PATH.
- Аудит публичных файлов и сохранение installer/checksum как CI-artifact.

Это не тест подписанного релиза, не проверка установки на Windows 11
и не проверка автообновлений/отката. Последующие результаты доступны в Actions.

Позднее подтверждён успешный [CI коммита 851d00a](https://github.com/sykia/umbrella-shell/actions/runs/39043020919)
с семью Windows CTest-проверками. Он предшествует изменению закрепления панели,
drag-and-drop и группам окон из `9b7146b`; переносить результат на них нельзя.
Новые проверки и просмотр их результатов при текущем обновлении документации
не выполнялись.
