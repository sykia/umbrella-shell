# Меню Umbrella на стандартной панели задач

После установки UmbrellaMenuHost запускается сразу, включая тихую установку.
Установщик добавляет для текущего пользователя HKCU Run / UmbrellaMenu со строго
заключённым в кавычки путём к UmbrellaMenuHost.exe --start. Закрытие окна настроек
не убирает пункт: помощник работает независимо от GUI и изменения оформления.
Он не заменяет Explorer, не меняет геометрию, прозрачность, автоскрытие или политики
оболочки. Qt, QML, D3D, сеть и системная служба ему не нужны.

По ПКМ на свободном месте стандартной панели показываются Umbrella, диспетчер
задач, параметры панели и «Завершить Umbrella». Umbrella возвращает скрытое/открытое окно установленного
UmbrellaShell.exe с проверкой полного пути процесса; иначе запускает соседний
UmbrellaShell.exe --settings по абсолютному пути. Диспетчер задач запускается
из системного каталога, параметры Windows — через ms-settings:taskbar.
Если exe отсутствует или запуск отклонён, показывается ошибка. Просмотр Python
не используется как подмена установленного приложения.

## Механизм и совместимость

Это собственная DLL в Explorer, отдельная от модуля размеров/островков.
WH_CALLWNDPROC ограничен потоками проверенных системных Shell_TrayWnd и
Shell_SecondaryTrayWnd, максимум 16 окон на одном проверенном UI-потоке;
сочетание панелей с разными UI-потоками отклоняется. Меню Windows 11 создаётся напрямую
XAML-функцией, поэтому WM_CONTEXTMENU и подписка ContextRequested не использованы.

Для текущей сборки проверяются RSDS GUID Taskbar.View.dll
24534974-E00E-46A5-8F69-F60D0CEB9BD9, age=1, RVA функции 0x7BFA30 и точные
18 байт полного пролога. На UI-потоке временно устанавливается переход в собственный
обработчик, создающий MenuFlyout. Отдельная RX-страница 4 КиБ хранит исходный пролог
и переход назад: при ошибке собственного меню вызывается исходная функция Windows.
Записи других перехватчиков не перетираются. После остановки исходные инструкции
восстанавливаются. На неизвестной сборке пункт не устанавливается, а штатное меню
остаётся доступным. Тексты команд помощника предусмотрены для русского/английского UI.

Постоянного опроса нет. TaskbarCreated и WinEvent SHOW инициируют подключение;
при незавершённом создании панели возможны до восьми попыток с одноразовыми таймерами.
Повторный запуск того же помощника не создаёт вторую сессию. Протокол оформления
панели не используется и не меняется.

## Остановка, обновление и удаление

UmbrellaMenuHost.exe --status проверяет наличие помощника; --stop останавливает его;
--open-settings отдельно выполняет ту же команду открытия настроек, что и пункт меню.
--quit-settings завершает GUI и его сеанс оформления; пункт «Завершить Umbrella»
использует ту же команду, оставляя установленный помощник меню работающим.
Установщик ждёт --quit-settings и --stop перед заменой файлов и перед удалением. Ошибка остановки
блокирует эти операции. Запись Run удаляется при uninstall; пользовательские настройки
сохраняются вне установки. При штатной остановке закрывается меню, отзываются Click-
обработчики, возвращаются инструкции, снимаются subclass/hooks, освобождается RX-страница.
Ожидание handle владельца возвращает меню после аварийного завершения помощника.
При зависшем Explorer или конфликтующей замене кода DLL сохраняет ограниченную safety-
ссылку вместо выгрузки исполняемого callback; это не гарантия восстановления после
одновременного сбоя или потери питания. Explorer принудительно не перезапускается.

Подписанная упаковка подписывает и проверяет все поставляемые exe/DLL, используя
уже заданный release-сертификат. Неподписанные сборки остаются только разработческими.

## Проверки

- DLL/host собраны MSVC 14.42 x64 с Windows SDK 10.0.26100.
- На двух текущих панелях подключение подтверждено; пользователь подтвердил появление
  Umbrella в настоящем меню ПКМ. Штатная остановка завершилась кодом 0, DLL выгрузилась
  из Explorer без его перезапуска. Повторный запуск и аварийное завершение только
  собственного помощника также проверены; после аварии DLL выгрузилась.
- taskbar_menu_patch_tests проверяет замену, вызов исходной функции, восстановление,
  повторную установку и отказ на неизвестных инструкциях в выделенной тестовой памяти.
- Test-MenuSettingsLaunch.ps1 проверяет запуск абсолютного sibling-пути с пробелами,
  аргумент --settings и ошибку отсутствующего exe. Вместо GUI выполняется отдельная
  тестовая программа; фактическая загрузка Qt этим тестом не подтверждается.
- Снимок работающего помощника: около 9,3 МиБ working set, 137 handles, 0,02 с CPU.
  Это разовое измерение, не проверка длительных утечек.

Полный C++ GUI, сборка/установка Inno Setup, upgrade/uninstall в VM, реальный logon,
перезапуск Explorer, другие сборки Windows, локализации и DPI/RDP не проверены.
Автозапуск в локальном окружении вручную не регистрировался: запись делает установщик.
