# Архитектура

Umbrella дополняет Windows; собственная оболочка и замена панели не создаются.
Core независим от Qt/Windows и содержит политику доверия обновлениям. App владеет
композицией, моделью TaskbarSettings и отдельным пользовательским QSettings INI.
Presentation содержит Settings.qml и TaskbarPage.qml. Qt Quick RHI владеет D3D11;
render остаётся границей зависимостей без второго устройства.

Platform/windows содержит WindowBackdrop, TaskbarState и TaskbarAppearance.
Win32 handles и Windows headers остаются в адаптерах. Собственные UmbrellaTaskbarHost
и UmbrellaTaskbarModule обслуживают размеры и нативную боковую раскладку внутри
Explorer. Windhawk не используется. Решение: TASKBAR_NATIVE_LAYOUT.md.

## Интерфейс и автоприменение

Loader, готовый логотип и первый frameSwapped завершают загрузку. Логотип плавно
останавливается, раскрывает надпись Umbrella, перемещается в правую колонку и
вращается только на видимом главном экране. Надпись возвращает главную; Taskbar
останавливает вращение и открывает настройки. Hover/контролы анимированы.

Автоприменение запускается только явными user-сигналами clicked/moved/toggled,
а не изменением bound properties при инициализации. Одноразовый Timer(180)
объединяет события. applyQueued сохраняется при pending; Connections.changed
перезапускает таймер после завершения native-запроса, не теряя последнее значение.
Восстановление останавливает отложенное применение. Периодического polling нет.
Ширина доступна при наличии собственного модуля, боковые кнопки — только для
проверенного сочетания трёх системных DLL. Проверка повторяется внутри Explorer
до изменения native-кэша; несовпадение отклоняет запрос.

## Native-адаптер

Верх/низ меняется недокументированным уведомлением расположения с проверкой
ABM_GETTASKBARPOS. Только HWND-проверка не доказывает корректность содержимого:
UI Automation выявила горизонтальные значки при одном лишь переносе HWND.
Собственная DLL теперь включает нативную вертикальную раскладку для проверенной
сборки и обрабатывает WM_WINDOWPOSCHANGING после штатного обработчика.
Каждая панель сохраняет свой монитор; меньшая ширина/длина вызывает штатный reflow,
а не обрезку трея. Кэш внутренней функции меняется только в Explorer на время сессии.

Alpha применяется ко всей панели со значками. Скруглённый регион имеет отступ
6 DIP. При смене только alpha не отправляется повторный перенос и не пересоздаётся
неизменившийся регион. При неизменном autohide ABM_SETSTATE не вызывается.
До первого изменения записывается атомарный журнал; новые снимки дописываются до
16 окон с ограничением региона 64 КиБ/окно. Проверяются системный путь Explorer,
HWND, PID и время создания процесса. Исходный журнал не переписывается на каждый
slider-сигнал без новых снимков.

Worker запускается тем же exe в режиме QCoreApplication --taskbar-watch и ожидает
handles родителя/stop event без GPU и polling. Native-изменения разрешаются после
ready. Восстановление проверяет идентичность окон. События геометрии объединяются
через out-of-context WinEventHook. Штатный выход возвращает край/alpha/регион,
но сохраняет явный выбор автоскрытия Windows. --restore-taskbar-style читает журналы.
Совместный сбой двух процессов, питание и зависание Windows API не покрываются.

WindowBackdrop отдельно оформляет только окно Umbrella через blur-behind. Это не
стиль системной панели. Frameless-окно перемещается startSystemMove.
Escape/Alt+F4 скрывают окно, сохраняя TaskbarSettings и сеанс оформления.
SettingsWindowLifetime отклоняет Close и вызывает hide; полный quit идёт отдельной
командой. SettingsWindowControl держит Win32-сообщения show/quit в platform,
возвращает скрытое окно через Qt и не допускает повторный обычный запуск того же exe.
Скрытие отключает постоянное хранение графики/scene graph и запрашивает
releaseResources; видимость уже останавливает анимацию главного экрана.
Smoke-режим сохраняет обычное закрытие. Полный выход по-прежнему выполняет RAII-
восстановление; геометрия и восстановительный worker не менялись. Подробнее:
SETTINGS_LIFETIME.md. Сетевого клиента, службы, тем/обоев и учёта активности нет.

Меню стандартной панели обслуживает отдельный UmbrellaMenuHost без Qt/GPU.
Установщик запускает его сразу и записывает HKCU Run только для этого помощника.
Скрытие/полное завершение GUI не завершает помощника. UmbrellaMenuModule временно перехватывает
точную проверенную функцию создания XAML-меню; неизвестная сборка отклоняется.
Протокол и время жизни этого модуля независимы от оформления/размеров панели.
При остановке восстанавливаются исходные инструкции и снимаются callbacks/hooks;
установщик ждёт завершения GUI и помощника перед обновлением или удалением файлов.
Границы совместимости и проверок: TASKBAR_CONTEXT_MENU.md.

## Проверки

QML tests/taskbar_live_ui_test.py проверяет debounce, отсутствие стартовой записи,
последнее изменение во время pending и недопустимые режимы, без изменения Windows.
Python/native-прототип проверил alpha/region, обычный возврат и восстановление после
смерти родителя. C++-код, installer/VM, DPI/RDP, полный multi-monitor и ресурсы не
проверены для полного GUI. Отдельные C++ DLL/host собраны; четыре стороны и размеры
проверены на двух мониторах 96 DPI, включая возврат после смерти host.
--ui-smoke проверяет QML/D3D11 и загрузочный переход; grabWindow не снимает
системный blur. Подробные текущие ограничения — TASKBAR.md.

Контекстное меню системной панели: [подключение и ограничения](TASKBAR_CONTEXT_MENU.md).

## Группы и толщина панели

Configuration v3 передаёт толщину 48–96 DIP и флаги islands/detached через собственный host.
Островки требуют минимум 64 DIP; QML выбирает 72 при включении. UIA-worker создаётся
только по первому включению, вне Explorer и GUI-потока. Он читает control type,
class, координаты и только идентификатор WidgetsButton у ToggleButton, без имён,
текста и AppID приложений. До 512 узлов объединяются в три семантические группы.
WinEvent-события Explorer объединяются одноразовым таймером 100 мс; при перестройке
дерева допускается до восьми повторов через 180 мс, постоянного опроса нет.

Host подтверждает островки после принятия масок всеми панелями; таймаут — 2500 мс.
DLL принимает маску только от владельца сессии и при совпадении текущего RECT,
проверяет количество/границы, строит прямоугольный регион ввода и сглаженный
CompositionGeometricClip для изображения. Пустые и
устаревшие маски отклоняются. Неизменная маска повторно не выделяет HRGN.
Исходный регион сохраняется при подключении и возвращается при выходе/смерти host.
TaskbarAppearance не перезаписывает регионы, пока островками владеет модуль.
Встроенные группы Windows (например, сеть/звук и часы/уведомления) не дробятся.

### Взаимоисключающие виды панели

В QML «Вид панели» выбирает один из attached/detached/islands. Для совместимости
с native-протоколом модель хранит два флага: attached=(false,false),
detached=(true,false), islands=(true,true). Старые сохранённые islands=true с
detached=false нормализуются без записи в Windows при открытии. Адаптер app также
нормализует islands -> detached и attached -> thickness=48 перед применением.

Оба ползунка размеров видны только в пользовательских видах; ширина/длина идёт
перед высотой/толщиной. selectStyle сохраняет толщину отдельной панели и островков
по отдельности на время жизни страницы. При автоскрытии выбор отдельной панели
сохраняет совместимую толщину 48; островки выключают autohide, его контрол в этом
виде недоступен. Сам выбор вида остаётся единым действием с debounce 180 мс.

### Согласование XAML с внешней геометрией

TaskbarVisualLayout работает на UI-потоке панели. Изменения только HWND/HRGN
оставляли подложку и нижнее выравнивание SystemTrayFrame в штатных 48 DIP, несмотря
на увеличенную область окна. Прямое изменение TaskbarFrame.Height оказалось
неподходящим: оно влияет на внутренний кэш высоты Explorer и мешает восстановлению.
Итоговая реализация не изменяет Width/Height нативных фреймов и кнопок.

Масштабируется только Taskbar.TaskbarBackground по короткой оси относительно центра;
сохраняется исходный RenderTransform. SystemTrayFrame получает Center alignment
по той же оси. Внутренние BackgroundStroke/ScreenEdgeStroke скрываются на время
добавленной толщины, чтобы штатная линия 48 DIP не оставалась внутри подложки.
SizeChanged обновляет коэффициент масштаба без polling. При обходе до 512 узлов
пропускаются поддеревья кнопок приложений и трея; текст не читается.

Локальные transform/origin, alignment и opacity сохраняются до первой мутации,
один раз на owner-сессию. Перед глобальной сменой стороны host сначала отправляет
SuspendVisuals всем своим панелям, затем применяет конфигурацию. Восстановление,
включая смерть owner, также снимает overrides соседних панелей до смены общей
стороны. Suspend возвращает только изменённые свойства, сохраняя первоначальный
снимок для следующих размеров. Callback/SizeChanged отписываются, HWND и регионы
возвращаются после снятия XAML overrides. Неизвестный root отклоняет дополнительную
толщину. Полное Qt C++ GUI и прочие DPI остаются непроверенными.

## Сглаживание и скрытые значки

TaskbarSmoothClip сохраняет Visual.Clip и BorderMode XAML-root. Окружности
задаются D2D geometry group через IGeometrySource2DInterop; физические пиксели
переводятся в DIP, BorderMode.Soft задаёт мягкое составление границы. D2D factory
многопоточная; геометрия создаётся для factory, запрошенной compositor. Отдельное
D3D-устройство, bitmap-маска и render-loop не создаются. Неизменная форма не
пересоздаётся. За краем экрана clip снимается для native hot zone автоскрытия.
HRGN ограничивает прямоугольные области ввода, а не сглаженный контур.

TaskbarPopupPlacement обслуживает только TopLevelWindowForOverflowXamlIsland и
NotifyIconOverflowWindow. На owning thread subclass корректирует WindowPos после
штатного расчёта; для другого UI-потока host использует WinEvent SHOW/LOCATIONCHANGE.
Состояние ограничено 16 popup HWND на панель, координаты — её монитором. Фокус и
z-order не меняются. Subclass снимается при завершении; обработчик ПКМ не изменён.

## Статус полной сборки

Упоминания локально не собранного GUI выше относятся к этапу native-прототипа.
Свежие результаты полного C++/Qt и границы проверок приведены в
[VERIFICATION.md](VERIFICATION.md). Это основной источник статуса сборки.
