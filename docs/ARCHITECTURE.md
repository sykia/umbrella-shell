# Архитектура

- `core`: независимые от Qt/Windows политики обновлений.
- `platform/windows`: Win32 AppBar, состояние автоскрытия, handles процесса
  восстановления, горячая клавиша, системные сообщения, opt-in HKCU Run и запуск системного Explorer.
  TaskbarSession — Qt Core адаптер; DesktopBar скрывает HWND через pimpl.
  Win32 handles и Windows headers не выходят в app/core.
- `app/ShellController`: композиция, QSettings INI, lifecycle окон, guard handshake,
  реакция на изменение экранов, аварийный выход и восстановление.
- `presentation`: QML панели и настроек; разделы настроек представлены моделью
  и StackLayout, новые страницы добавляются независимо от панели.
- `render`: граница зависимостей D3D11/DXGI. Фактическим устройством и его
  жизненным циклом владеет Qt Quick RHI; отдельное устройство не создаётся.

## Жизненный цикл панели

Один экземпляр на Windows session, mutex сохраняется открытым также guard-процессом
до завершения восстановления. Создаются окна по QScreen с геометрией в DIP.
Первый frameSwapped каждого окна → запуск guard → ready event → синхронная запись
журнала → ABM_SETSTATE(auto-hide) → arm event → guard скрывает окна Explorer →
applied event → ABM_NEW/QUERYPOS/SETPOS для каждого HWND.
Если стадия не удалась, исходный режим Windows восстанавливается.
AppBar резервирует рабочую область в физических координатах монитора.
Повторное уведомление с той же геометрией не порождает цикл перестановок.
Fullscreen-уведомление временно опускает панель; активация и геометрия окон
обрабатываются Windows и Qt. Изменение экранов/DPI пересоздаёт панели после
восстановления Windows. TaskbarCreated инициирует повторную регистрацию.

Guard — тот же exe в режиме QCoreApplication без GPU, ожидающий handles
основного процесса, stop/arm events и очереди Win32 сообщений. TaskbarVisibility
устанавливает out-of-context WinEventHook и хранит не более 64 идентичностей окон
(HWND, PID, время создания процесса, исходная видимость). Только окна известных
классов из системного explorer.exe допускаются к скрытию. При восстановлении
сначала снимается hook, затем возвращается видимость ещё существующих окон.
CREATE невидимого окна не сохраняется как исходно скрытая панель; первый SHOW
нового Explorer фиксируется перед скрытием. При смерти родителя или сигнале восстановления
возвращает исходный флаг ABS_AUTOHIDE, сохраняя прочие текущие флаги Windows.
Основной процесс также восстанавливает состояние при штатном выходе, shutdown
и неожиданном завершении guard. При неожиданном выходе guard замена отключается и GUI завершается.
Журнал в QSettings используется после совместного сбоя процессов; восстановление
не гарантируется во время отключения питания или блокировки Windows API.

Настройки вне установки, QSettings IniFormat/UserScope, атомарная синхронизация
Qt, ошибки записи блокируют включение замены. Значения: shell/replacement,
recovery/pending и recovery/autoHide. Автозапуск читается из собственного значения
HKCU Run с проверкой абсолютного quoted executable path. Секреты не сохраняются.
Uninstaller удаляет запись Run и запускает recovery; пользовательские данные
сохраняются. Ни installer, ни приложение не меняют Winlogon или shell policies.

PanelActions изолирует запрос языка foreground-потока, WM_INPUTLANGCHANGEREQUEST,
открытие ms-settings:sound и SendInput штатных сочетаний рабочих столов.
Раскладка обновляется coarse-таймером 750 мс только для активного модуля.
Контроллер хранит валидированные panel/edge и panel/modules/* в QSettings.
Проверка допустимых значений независима от Windows/Qt (core/PanelConfiguration.h).
AppBar принимает четыре края, для боковых панелей резервируется ширина 56 DIP.
Frameless настройки имеют фиксированные 680×440; логотип toggles show/hide.
FrameAnimation логотипа останавливается вместе с невидимой страницей/окном.
Сетевых запросов нет. Два процесса в активном
режиме: GUI и заблокированный на handles guard. D3D11 используется только GUI.
Тестовый `--ui-smoke` содержит одноразовый таймер; он не меняет панель Windows.
Измерения ресурсов и ручная матрица: [SHELL_BAR.md](SHELL_BAR.md).
