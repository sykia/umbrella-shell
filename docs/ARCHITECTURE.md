# Архитектура

- `core`: независимые от Qt/Windows политики обновлений.
- `platform/windows`: Win32 AppBar, состояние автоскрытия, handles процесса
  восстановления, горячая клавиша, системные сообщения, opt-in HKCU Run и запуск системного Explorer.
  TaskbarSession — Qt Core адаптер; DesktopBar скрывает HWND через pimpl.
  Win32 handles и Windows headers не выходят в app/core.
- `app/ShellController`: композиция, QSettings INI, lifecycle окон, guard handshake,
  реакция на изменение экранов, аварийный выход и восстановление.
- `presentation`: QML панели и настроек; разделы настроек представлены моделью
  и StackLayout, новые страницы добавляются независимо от панели.
- `render`: граница зависимостей D3D11/DXGI. Фактическим устройством и его
  жизненным циклом владеет Qt Quick RHI; отдельное устройство не создаётся.

## Жизненный цикл панели

Один экземпляр на Windows session, mutex сохраняется открытым также guard-процессом
до завершения восстановления. Создаются окна по QScreen с геометрией в DIP.
Первый frameSwapped каждого окна → запуск guard → ready event → синхронная запись
журнала → ABM_SETSTATE(auto-hide) → arm event → guard скрывает окна Explorer →
applied event → ABM_NEW/QUERYPOS/SETPOS для каждого HWND.
Если стадия не удалась, исходный режим Windows восстанавливается.
AppBar резервирует рабочую область в физических координатах монитора.
Повторное уведомление с той же геометрией не порождает цикл перестановок.
Fullscreen-уведомление временно опускает панель; активация и геометрия окон
обрабатываются Windows и Qt. Изменение экранов/DPI пересоздаёт панели после
восстановления Windows. TaskbarCreated инициирует повторную регистрацию.

Guard — тот же exe в режиме QCoreApplication без GPU, ожидающий handles
основного процесса, stop/arm events и очереди Win32 сообщений. TaskbarVisibility
устанавливает out-of-context WinEventHook и хранит не более 64 идентичностей окон
(HWND, PID, время создания процесса, исходная видимость). Только окна известных
классов из системного explorer.exe допускаются к скрытию. При восстановлении
сначала снимается hook, затем возвращается видимость ещё существующих окон.
CREATE невидимого окна не сохраняется как исходно скрытая панель; первый SHOW
нового Explorer фиксируется перед скрытием. При смерти родителя или сигнале восстановления
возвращает исходный флаг ABS_AUTOHIDE, сохраняя прочие текущие флаги Windows.
Основной процесс также восстанавливает состояние при штатном выходе, shutdown
и неожиданном завершении guard. При ошибке guard замена отключается и открываются
настройки; штатный сигнал аварийного восстановления завершает GUI.
Журнал в QSettings используется после совместного сбоя процессов; восстановление
не гарантируется во время отключения питания или блокировки Windows API.

Настройки вне установки, QSettings IniFormat/UserScope, атомарная синхронизация
Qt, ошибки записи блокируют включение замены. Значения: shell/replacement,
recovery/pending и recovery/autoHide, а также panel/edge и panel/modules/*.
Журнал на диске хранит режим taskbar, а не список скрытых приложений.
Автозапуск читается из собственного значения
HKCU Run с проверкой абсолютного quoted executable path. Секреты не сохраняются.
Uninstaller удаляет запись Run и запускает recovery; пользовательские данные
сохраняются. Ни installer, ни приложение не меняют Winlogon или shell policies.

PanelActions изолирует запрос языка foreground-потока, WM_INPUTLANGCHANGEREQUEST,
открытие ms-settings:sound. В адаптере сохранены вспомогательные SendInput-вызовы
штатных сочетаний, но текущие кружки групп окон их не используют.
Раскладка обновляется coarse-таймером 750 мс только для активного модуля.
Контроллер хранит валидированные panel/edge и panel/modules/* в QSettings.
Проверка допустимых значений независима от Windows/Qt (core/PanelConfiguration.h).
AppBar принимает четыре края, для боковых панелей резервируется ширина 36 DIP.
Frameless настройки имеют фиксированные 680×440; логотип toggles show/hide.
FrameAnimation логотипа останавливается вместе с невидимой страницей/окном.
Сетевых запросов нет. Два процесса в активном
режиме: GUI и guard, ожидающий handles и очередь сообщений. D3D11 используется только GUI.
Тестовый `--ui-smoke` содержит одноразовый таймер; он не меняет панель Windows.
Измерения ресурсов и ручная матрица: [SHELL_BAR.md](SHELL_BAR.md).

## Группы окон на мониторах

MonitorWorkspaces реализует от 1 до 10 групп обычных окон на каждом HMONITOR.
Количество по умолчанию — 5, сохраняется в panel/workspaceCount; перед изменением
все скрытые окна возвращаются и группы сбрасываются. Это исключает потерю доступа
к окнам удаляемых групп. Кнопки QML имеют постоянную геометрию и живут до изменения
количества: обновление состояния не пересоздаёт делегаты и не обрывает анимации.
Это собственное управление видимостью, а не IVirtualDesktopManager Windows.
Для frameless приложений допускается WS_EX_APPWINDOW без WS_CAPTION; owned,
tool и no-activate окна исключены. Select сначала публикует recovery intent,
затем применяет SWP_SHOWWINDOW/HIDEWINDOW одним DeferWindowPos-пакетом с
NOMOVE/NOSIZE/NOACTIVATE/NOZORDER/NOOWNERZORDER. Видимость проверяется до смены
активного индекса; ошибка пакета или публикации вызывает возврат окон.
Это не compositor и не анимация всего экрана; синхронные Win32 callbacks могут
задержать GUI. Проверки QML отдельно проверяют маршрутизацию индексов и сохранение
делегатов, а fixture Windows — видимость и placement синтетических окон.
Scoped discovery исключает окна GUI/guard, owned/tool/elevated/cloaked окна;
в тесте discovery дополнительно ограничен PID синтетического child process.
Обновление 500 мс работает только при включённом модуле. Состояние групп не
переживает перезапуск: при выходе все скрытые менеджером окна возвращаются.
Ограничения: 16 мониторов и 256 обычных окон; окна сверх лимита не группируются.
Повторный показ скрытого окна приложением подавляется на очередном обновлении,
поэтому отсутствие краткого появления не гарантируется.

Перед SW_HIDE identity окна (HWND, PID, process creation time, show command)
публикуется в shared mapping. Два буфера и атомарный published index сохраняют
последний целый снимок при смерти writer внутри записи. Named mutex ограничивает
конкурентный доступ; guard удерживает mapping до завершения восстановления.
Порядок выхода: возврат групп окон → снятие hook taskbar → исходный auto-hide.
При изменении топологии/края группы также возвращаются до пересоздания панелей.
Одновременная принудительная смерть GUI и guard не покрывается shared-memory
снимком; это ограничение нельзя считать решённым обычным recovery CLI.

DesktopBar якорится к физическому краю монитора; ABM_QUERYPOS/SETPOS согласуют
рабочую область отдельно и больше не двигают окно вслед за taskbar Explorer.
ABN_FULLSCREENAPP снижает z-order только при подтверждённом полноэкранном окне.
ModuleConfiguration переносит настоящие модули через Drag/DropArea с возвратом
при отмене; сохранение конфигурации выполняется только после принятого drop.

Эти изменения описывают реализацию, а не результат испытаний. Проверки текущих
групп окон, закрепления панели и drag-and-drop отложены на 2026-10-17;
двухмониторная GUI-проверка и измерения ресурсов остаются обязательными.

TaskbarCreated объединяется одноразовым таймером 100 мс, поскольку broadcast
получает каждое окно процесса. События геометрии/DPI объединяются за 150 мс;
это не периодический polling. ABN_POSCHANGED обрабатывается queued, вне native
callback. Изменение только z-order не уведомляет AppBar о новой геометрии.
Кэшируется согласованный резерв отдельно от фактического прямоугольника окна;
повторное позиционирование сохраняет fullscreen z-order. Перед восстановлением
Explorer снимаются собственные AppBar-резервы. Эти изменения пока не испытаны.

Preferences в app владеет оформлением и отдельным QSettings INI статистики.
DesktopIntegration изолирует Win32 wallpaper, foreground exe и secure-desktop.
Учёт opt-in: coarse 5 секунд, flush раз в минуту/выход, до 90 дней и 100 exe в сутки.
Отдельный activityChanged не обновляет палитру и не пересоздаёт панель.
Шрифты загружаются только в процесс, без системной установки.

По уточнению владельца учитывается всё время активного окна, включая отсутствие
ввода и Umbrella. Фоновые приложения одновременно не суммируются; блокировка
и сон исключены. Переход между окнами имеет погрешность до одного 5-секундного
интервала. Кнопки/поля новых вкладок используют общий скруглённый стиль.
