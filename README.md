# Umbrella Shell

Панель для Windows 11 x64: C++20, Qt 6.8.3 / QML, Win32 AppBar и D3D11
через Qt Quick RHI. Обычный запуск создаёт панель высотой 36 DIP на каждом
мониторе. Слева находится логотип Umbrella, открывающий настройки.
На панели доступны независимые группы окон на мониторах, раскладка активного
приложения и открытие параметров звука Windows. Настройки 680×440 без системного
заголовка показываются/скрываются кнопкой Umbrella. Приветственная страница имеет
анимацию логотипа с ускорением и увеличением при наведении.
Настройки используют светлую тему с красным акцентом и собственные SVG-иконки.

Состояние на 2026-10-17: последние изменения закрепления панели, перетаскивания
и групп окон реализованы в исходниках, но их работа на двух мониторах Windows 11
пока не подтверждена. Дальнейшие сборки, тесты и GUI-запуски отложены по запросу
владельца. Описание возможностей не заменяет проверку текущей сборки.

В разделе «Панель» выбирается один из четырёх краёв и размещение каждого модуля:
доступные / слева / по центру / справа (для вертикальной панели — начало / центр / конец).
Модули перетаскиваются между зонами; слева/центр/справа показаны горизонтально.
Подсказки поверх кнопок панели убраны; имена доступны через accessibility.

Пространства Umbrella — собственные группы окон, а не виртуальные столы Windows.
Пять кружков на каждой панели переключают окна только её монитора: заполненный
кружок содержит окна, красная капсула обозначает активную группу. Новые окна
относятся к текущей группе, перенос окна на другой монитор — к его текущей группе.
Системные Win+цифры / Win+Ctrl+←/→ не меняются.

В настройках можно отключить замену панели, включить запуск при входе в Windows
и завершить Umbrella с восстановлением Windows. Автозапуск по умолчанию выключен;
он использует только HKCU Run. После установки предлагается запуск приложения.
Настройки INI хранятся вне установки, в пользовательском каталоге Qt;
удаление сохраняет их, но удаляет запись автозапуска.

## Безопасность и ограничения

Explorer продолжает работать; системные файлы и shell policies не меняются.
После первого кадра всех Umbrella-панелей и готовности guard включается штатное
автоскрытие для освобождения рабочей области, затем guard скрывает окна
`Shell_TrayWnd` и `Shell_SecondaryTrayWnd` через ShowWindow(SW_HIDE).
У каждого окна проверяются путь системного explorer.exe и идентичность процесса.
WinEventHook вне процесса реагирует на создание/показ/перемещение панелей,
включая новые панели после перезапуска Explorer. Для подавления taskbar нет
injection или polling; таймеры модулей описаны ниже.

Это более сильное подавление, чем auto-hide, но **не публичный контракт Windows**:
имена классов принадлежат реализации Explorer, out-of-context события асинхронны.
Нельзя гарантировать отсутствие даже одного кадра повторного появления на всех
сборках Windows. Успешное скрытие проверяется через IsWindowVisible и
`--taskbar-status`; проверка краёв экрана и обоих мониторов должна выполняться
на конкретном рабочем столе. Результаты локального теста записываются отдельно.

При обычном выходе и завершении основного процесса процесс восстановления
снимает hook, показывает скрытые им окна и возвращает исходный флаг автоскрытия.
Он ожидает handles и очередь Win32 сообщений без polling.
Если исходно автоскрытие было включено, оно сохраняется. Двойной сбой обоих
процессов, принудительное завершение дерева, отключение питания и зависание
GUI не покрываются одним ожиданием процесса. Журнал и отдельная recovery-команда
позволяют восстановить системную панель, но не являются журналом групп окон.
Снимок скрытых приложений существует только в общей памяти GUI/guard: при
принудительном завершении обоих процессов его восстановление не гарантируется.

Аварийный выход: **Ctrl+Alt+U** либо кнопка в настройках. Если сочетание занято,
настройки показывают предупреждение. Через Task Manager → Run new task можно
запустить установленный `UmbrellaShell.exe --restore-taskbar` (отключает замену
и подаёт сигнал процессу восстановления). Ярлык **Restore Windows taskbar**
в меню Пуск вызывает ту же команду. `--restore-explorer` отдельно запускает
системный Explorer по абсолютному пути; он не ремонтирует реестр.

Анимация работает только на видимой приветственной странице. Индикатор раскладки
опрашивает foreground thread раз в 750 мс, только пока модуль включён и панель активна.
Менеджер групп обновляет список окон раз в 500 мс только при включённом модуле;
лимиты — 16 мониторов, 256 обычных окон. Tool/owned/elevated и cloaked окна не
группируются. Это не compositor: повторный показ окна приложением может быть
подавлен лишь на следующем обновлении. Не смешивайте оценку групп с независимыми
виртуальными столами Windows — последние остаются общими для экранов.
В отключённом модуле таймер остановлен. Нет сетевого клиента или второго
D3D device поверх Qt. Blur пока не реализован: панель непрозрачна, будущие
эффекты должны оставаться в слое presentation/rendering с отдельными замерами.
Автообновления отключены до выполнения [условий доверия](docs/UPDATES.md).

## Сборка и проверки

Windows 11 x64, Visual Studio 2022 Desktop C++, Windows SDK, CMake >= 3.25,
Qt 6.8.3 `msvc2022_64`, Inno Setup 6.4.3. В Developer PowerShell:

```powershell
$env:CMAKE_PREFIX_PATH = 'C:\Qt\6.8.3\msvc2022_64'
cmake --preset windows-msvc
cmake --build --preset release
ctest --preset release
./scripts/Build-Package.ps1
```

Упаковка требует отсутствующий каталог `stage`, развёртывает Qt/QML imports,
создаёт per-user unsigned installer в `dist/`. Несертифицированная сборка
предназначена для разработки. Настройки и GUI не запускаются установщиком молча.
`--diagnostics` печатает JSON без инициализации GPU.
`--ui-smoke` загружает оба QML-экрана и логотип, проверяет отрисовку D3D11,
выводит число кадров и working set, затем выходит; панель Windows не меняет.
Это проверка ресурсов/рендера, а не интеграционный тест замены панели.
CI также сохраняет PNG всех четырёх страниц настроек. Поля раскладки зависят
от foreground приложения; elevated окна могут отклонить смену языка (UIPI).
Реальные клики, клавиатура и переключение рабочих столов требуют desktop-проверки.

Core без Qt:

```powershell
cmake -S . -B build/core -DUMBRELLA_BUILD_APP=OFF -DBUILD_TESTING=ON
cmake --build build/core --config Release
ctest --test-dir build/core -C Release --output-on-failure
```

Запускайте `scripts/Test-Foundation.ps1` и `scripts/Test-PublicRepository.ps1`
перед коммитом. Результаты CI видны в Actions; ручная матрица испытаний и
ограничения измерений описаны в [SHELL_BAR.md](docs/SHELL_BAR.md).
